# Optimization history

This is the repository's single history of attempted performance work. Entries
retain only the hypothesis, disposition, and durable lesson. They do not define
current behavior; current contracts live in architecture and subsystem docs.

`Accepted` means the useful mechanism remains or its result became product
policy. `Rejected` means the candidate was removed or disabled. `Measured`
means the work improved understanding without justifying a product change.

## General gadget forwarding

| Attempt | Disposition and lesson |
| --- | --- |
| Template-owned adjacent scalar result forwarding | Accepted as the default policy; `BuildOptions` can still disable it per program for controls. Shared assembly operand contracts select a forwarding variant from the decoded entry rather than from an opcode-pair whitelist. Dependent scalar probes ran two to three times faster while full workloads showed broad coverage rather than a general speedup, and a mechanism control must match both the code layout and the data addresses of its arm. |
| Template-owned adjacent SIMD/FP result forwarding | Accepted as a default beside scalar forwarding. Natural-v2 contracts extend the shared SIMD/FP templates without new hot-path producer copies. Geekbench gains were small against shared-host variation, so correct forwarding coverage is not a broad speedup claim. |
| Combined scalar/SIMD dependency coverage | Measured with both policies enabled. Broad contract coverage did not imply frequent adjacent dependencies: SIMD added only a few points of entered-instruction coverage. Coverage counts execution-weighted opportunities, not retired reads or speedup; the diagnostic was later removed. |
| Preserve results across opposite-domain gadgets | Measured, not enabled. Preserving results across audited nonclobbering opposite-domain entries added about a tenth of a point of coverage, too little to justify separate preservation contracts. |

## 4 KiB page path

| ID | Attempt | Disposition and lesson |
| --- | --- | --- |
| G263 | Give the 4 KiB software TLB the 16 KiB geometry: 16,384 two-way sets indexed directly by page number | Rejected. The M4 MacBook Air stayed level on 4 KiB Geekbench, but the iPad mini 6 lost 2% single-core in every run and both hosts lost 12% on Navigation. The likely cause, not proven, is cache footprint: one 64-byte line per page, where the one-way folded table packs two pages to a line, costs a pointer-chasing working set more in misses than the extra reach saves. G265 doubled the one-way table instead. `arm64-tlb-probe-set` stayed. |
| G264 | Fill a 4 KiB TLB miss's whole 16 KiB group: one static-MMU lookup returns all four pages and the miss installs each mapped one | Rejected: single-core Geekbench stayed level on the M1. Two thirds of 4 KiB misses find another page of their group already cached, but installing the other three evicts live entries from the direct-mapped table (misses rose 43%), and installing only into free slots finds almost no room (98% of misses land in an occupied slot). The 4 KiB miss stream is capacity and conflict, not cold. |
| G265 | Give the 4 KiB software TLB 16,384 one-way entries indexed directly by page number, with the page-crossing test moved to the miss path | Accepted. The table doubles to 512 KiB per vCPU but still packs two pages to a line, and the hit path loses the index fold and the front crossing test: a direct index never puts a page and its successor in one slot, so a crossing access always misses and the miss path finds it. On the iPad mini 6, 4 KiB Geekbench gained 4.0% single-core and 3.8% multi-core with every workload ahead (Navigation 7.5%, where G263 lost 12%); against 16 KiB it now scores 1.008 and 1.003 (0.969 and 0.961 before). The same direct index with half the entries and a line shared by neighbouring pages wins where one line per page lost. |
| G266 | Fault 4 KiB anonymous writes in aligned 16 KiB blocks, and keep the per-CPU page lists at their minimum high mark | Rejected. Against the folded 4 KiB table it moved iPad single-core +0.7% and multi-core +1.1%, too little to repay what it costs: it gives back the sparse anonymous footprint that 4 KiB pages buy, which Android guests depend on most, it would be a shared kernel topic that rebuilds every line, and its page-list limit departs from upstream. |
| G269 | Publish a kernel write into guest code only once x86 code may run | Accepted. Every 4 KiB uaccess write is copied back into the guest page and published a code change whenever the page was guest code, so with an executable stack nearly every system call that wrote its result there reset the shared space's links. Only an x86 dispatch now turns the publication on (arm64 and AArch32 see such a write only after their own cache maintenance). Slot validations per Aquarium frame fell from 12,400 to 2,800 (16 KiB: 1,450) and 4 KiB Aquarium rose 6.8% on the M1 Ultra. Compare both page profiles' event counts, not only their times: a path only one takes can carry a cost the other never pays. |
| G270 | Fill a gadget TLB miss through the executor's entered execution context | Accepted. A miss resolved the thread's address space through the registry and the thread's active generation, and each Darwin `thread_local` access is a `_tlv_get_addr()` call that cost more than the page lookup. The miss now uses the entered context, which already holds that state: `guest_process_switch_loop` ran 32% faster at both page sizes and Aquarium stayed within noise. On a Darwin hot path, pass a resolved object down instead of looking it up through `thread_local` per call. |
| G271 | Attribute the 4 KiB Aquarium gap | Measured on the M1 Ultra. 4 KiB spent 14.3% more vCPU time per frame than 16 KiB, split between gadget execution (41% of the difference), program-cache revalidation after G269's publications (29%), TLB fills (11%) and the guest kernel (14%); no extra page-boundary block splitting was found. G269 and G270 cut the gap to 3.3%. What remains is a fifth fills and a quarter two 4 KiB-only kernel paths: a uaccess bridge call per page that shared kernel aliases made redundant, and init_mm slot synchronization over a purged vmap range. |
| G273 | Fill an entered context's TLB miss from a lock-free radix index of its generation's mappings | Accepted. A TLB fill took the mapping map's reader lock, a cache line every vCPU writes, then missed on a hash node per page, and a 4 KiB guest refills about twice as often as a 16 KiB one. A lock-free radix index of atomic words (64-page leaves) now answers it; every removal or change of a mapping already quiesces execution, so a reader never sees a stale word, and an absent one sends it to the map. TLB fill time per Aquarium frame fell from 1.7-2.6 to 0.6-0.7 ms at 4 KiB on the Mac. The index costs 29 bytes per mapped page at 4 KiB against about 72 for the map. |
| G274 | Answer a 4 KiB uaccess backing sync under one lock | Accepted. Every page kernel uaccess touches on 4 KiB pages ran `darwin_uml_vm_sync_from_backing()`, which took the space's lock twice and the ownership registry's once although the page is nearly always mapped directly. One hold of the space's lock now answers it, and only a range past the space's direct slots asks the registry: 4 KiB Aquarium vCPU time spent there fell from 0.36% to 0.26%. The call stays, because a host-private shadow slot must still be refilled from its backing. |
| G275 | Read the Darwin carrier CPU from the thread's TSD instead of calling `pthread_getspecific()` | Accepted, kernel release p4k1. Every use of `current` asked the carrier's pthread key through the PLT: 3.5% of vCPU time on the iPad in Aquarium and 0.8% to 1.5% on the Mac. Kernel-owned state cannot answer (signal handlers run kernel code on the sigaltstack, and XNU owns `TPIDR_EL0`), so the kernel keeps each carrier's CPU number in a second key and loads its word at `TPIDRRO_EL0` plus key times 8, behind a per-carrier check against `pthread_getspecific()` that turns the read off on a mismatch. A getpid loop fell 22%. An inline read was no faster and added 475 KB of kernel text. |
| G276 | Apply only changed `init_mm` PTEs in a kernel TLB sync | Accepted, kernel release p4k2. A kernel-range walk mapped every present PTE again, and a vmalloc purge flushes the whole span between the areas it frees (vfree of vmapped kernel stacks and seccomp's BPF programs trigger it often). The walk now applies only PTEs carrying `_PAGE_NEEDSYNC` and clears the bit by compare-and-exchange. A fork-burst loop ran 38% faster at 4 KiB and 42% at 16 KiB; in Aquarium the sync is bimodal (about 0.4 ms per frame when a purge lands), which fps cannot resolve. |
| G277 | Invalidate arm64 translated code only over the changed range | Rejected before it was built. A counting build (Aquarium, 2 vCPUs, 2 GiB, two runs per profile) showed 4 KiB translating and validating no more than 16 KiB: 5.8 against 7.6 thousand translations and 6.5 against 6.2 thousand body validations per frame. Only epoch advances differ, 32 against 20 per frame, and all validation together costs at most 0.55 ms per frame, about 0.4% of vCPU time, which bounds what a precise invalidation could recover. |
| G278 | Plan no page for a batch unmap that names a page nothing holds | Accepted. A 4 KiB guest's TLB replay sends one unmap per absent PTE, and the host planned every page of each unmap before finding it empty: 14,700 pages per Aquarium frame against 5,700 at 16 KiB, none mapped, because the host removes a page when Linux invalidates it. An unmap now plans only pages its generation or an earlier operation of the batch holds, and the batch commit fell from 1.18 to 0.84 ms per frame. |
| G279 | Send neighbouring Darwin user PTEs as one host call | Accepted, kernel release p4k4. A user replay made one host call per PTE: 4,200 maps and 14,200 unmaps per 4 KiB Aquarium frame against 980 and 5,600 at 16 KiB, most in long runs of empty PTEs. The walk now sends a run of absent PTEs, or of PTEs mapping consecutive offsets of one backing with one protection, as one call: maps fell by a third, unmaps by 97% and the Mac's TLB sync from 1.96 to 1.52 ms per frame. A dropped run cannot be observed, because an absent page faults back in; `guest-tlb-replay-runs` catches a run that merges protections or offsets. |
| G281 | Remove the 16 KiB guest page profile | Accepted, superseding G37. After the one-way 4 KiB TLB (G265) and the work that followed, the 4 KiB profile matched the 16 KiB one where users see it: iPad mini 6 Geekbench 4K/16K 1.008 single-core and 1.003 multi-core, and WebGL Aquarium 1.017 on the iPad and 0.988 on the M4 MacBook Air. Keeping both profiles cost a second TLB geometry, a second profile in every unit, integration, corpus and runner matrix, and a second runtime framework in the app, against about 100 MiB more page map per 8 GiB guest at boot. The host page stays 16 KiB. Lesson: G37's gap closed once the 4 KiB path was optimized, so re-measure a default chosen to avoid a gap after the gap's causes are worked on. |

Give freed memory back to the system, not to a heap, and let a hole serve any size; map an arena that grows in a few large steps and drop a dying one whole. |
| G258 | Keep emptied arm64 arena chunks in a process-wide set for the next arena | Rejected. Mapping each chunk itself (G257) turns every emptied chunk into an munmap and every new one into an mmap and its page faults: replaying an Aquarium run, the arenas took 326,000 faults against 79,000 for the heap-backed arenas. A set keeping up to 256 emptied chunks (16 MiB) for whichever arena asked next served four in five requests and cut the faults to 122,000, but Aquarium and Geekbench 6 stayed level and the arenas' share of time could shrink by under half a percent. What cost load time was the arena's own work per chunk and per freed body, which G257 removed with regions and whole-space drops. A reserve of 128 chunks that expired after a quarter second halved the faults but cost what G257 saved in footprint, so it was not built. Price what a mapping costs in the workload before spending footprint to avoid it. |
| G262 | Make the two ends of a CpuState hop around an in-place entry agree in addressing form | Rejected. Hops that mix a baked and an indexed access to one guest register are 22 percent of A64 register reads and 9.5 percent of A32's, almost all a baked writer read by an indexed reader, which costs exactly an indexed hop; only the reverse costs more. Sampling the most mixed workloads found no excess in any in-place family, unlike G251's fold. Adapters that store or load the baked slot again won up to 38 percent on latency-bound probes, but the load half cost GB6 single-core 2 percent. A hop-form fix that adds work pays only where the hop is on the critical path, and a probe built around one chain overstates it. |
| G267 | Replace a shared gadget space whose arena is mostly freed | Accepted. G227's shared space lives while any executor's window holds it, so under Aquarium's process churn it kept the link records and freed-body arena that private copies shed: before G257 it averaged 135 to 168 MiB against 102 to 115 private, with half its arena free and about two thirds of its link records named by no resident body. Sweeping the records as a private space does (G256) needs every executor's slots, memos and return rings read together; it was designed and not built. A shared space instead counts the bytes of its arena and of the bodies some slot holds, and once at least 2 MiB are unused and more than its bodies use, the executor that let go of a body or stored one closes it: it leaves the registry, so the next executor to run the address space gets a new one, every attached executor lets go of the old one at its next entry into translated code, and it dies with its last executor. With G257's arena, Aquarium's shared cache averaged 84 MiB against 116 private (-27%), and 137 MiB with replacement off, so the bound is what matters; Geekbench 6 multi-core held 80 MiB against 177 private. A lifetime that a sweep would need cross-executor reachability to bound can be bounded by replacing the container once enough of it is dead. |
| G268 | Share an address space's translations among its executors by default | Accepted. With G267 bounding a shared space, sharing was measured against private in one binary on the merged tree, with main as the control for the private path. Private against main was level, so G267 cost the private path nothing. Shared against private was level on the M1 Ultra (Geekbench single-core 154 against 156, multi-core 526 against 518.5, Aquarium 17.7 against 17.2 frames per second), the M4 MacBook Air (Aquarium 27.0 against 26.7, peak resident size 2% lower) and the iPad mini 6 (multi-core 237 against 235.5, peak footprint 1,750 against 1,758 MiB). Memory and scores both held, so a host with FEAT_LSE2 (every Apple Silicon product) shares unless `DARWIN_UML_GADGET_SHARED_BODIES=0`; x86 links cannot be retargeted with one atomic store and stay private. A shared space is not swept (G256), and renewal replaces it instead. |
| G272 | Let go of the gadget spaces of address spaces the kernel destroyed | Accepted. The kernel numbers every mm it creates, never reuses a number, and destroys the generation when the mm's last reference goes, after which nothing can run it. A gadget executor's window nevertheless kept the translations, link records and indirect sites of the eight address spaces it ran last until newer ones displaced them, and a Geekbench process, whose boot-time processes exit early, never displaces them: those dead spaces held 11.1 MiB of multi-core Geekbench's 78.7 MiB shared mean and about 3 MiB of Aquarium's. The MMU now counts destroyed generations; an arm64 executor compares the count at every entry into translated code and, when it moved, lets go of each space, in every SVCR mode cache, whose generation the MMU reports destroyed, as it lets go of a closed shared space. The number keeps its place in the window's order as a tombstone that the least-recently-used rule drops with no work, so live spaces are displaced exactly when they were (freeing the place too admitted a newer live space and grew shared Aquarium's cache by 14%, the larger window G229 priced). Multi-core Geekbench shared averaged 67.2 MiB against 78.2 (-14%), with hit rates and stores level, and Aquarium 10% less. Timing on the M1 Ultra and the M4 MacBook Air stayed level; the change adds one load per entry (about 0.005%) and leaves the gadget bank's objects byte-identical. A holder of state keyed by something its owner can say is dead should drop it when told, and keep that state's place in a recency order, so that retiring the dead changes nothing about the live. |
| G280 | Settle the gadget-cache slot count at 262,144 on both products and both ISAs | Accepted, ending G232's interim 131,072. 65,536, 131,072 and 262,144 slots were built from one commit (eight ways, shared bodies) and timed with Geekbench and WebGL Aquarium on the M1 Ultra pool, the M4 MacBook Air and the iPad mini 6. 262,144 was not significantly behind the best size on any metric or host. Against 131,072 it gained single-core Geekbench 1.7% on the M1 Ultra, multi-core 1.2% on the iPad and a 2.3% faster Aquarium load on the M4; 65,536 loaded Aquarium 9.4% slower on the M1 Ultra and 3.0% slower on the M4. The 262,144-slot build moves 17,555 of 50,246 symbols, so 131,072 slots padded into that layout separated the two: layout alone moved single-core 0.2%, the slot count alone +4.3% on the M1 Ultra. The price is memory: four-vCPU census means grew 11 to 14 MiB on arm64 and 55 MiB on x86 multi-core Geekbench, whose score did not move, and none of the iPad's 30 launches was killed. At 262,144 the arm64 workloads fill 40 to 78% of their slots and evict almost nothing. Settle a capacity where the measured workloads stop evicting, and check with a layout control that a size-changing build's gain is the size's own. |
| G282 | Bound the bytes the gadget caches keep with a per-process budget | Accepted. A slot count bounds how many translations a cache keeps, not their bytes (G280), and the iPad mini 6 kills the process at 2,867 MiB. Both gadget engines now charge what each address space keeps (an arm64 space its arena chunks, oversized blocks, link and indirect records and target table, once however many executors attach; an x86 address space its translations, records and target tables) to one process-wide budget; slots are not charged. A store that takes the open accounts past the budget asks the largest to shed until the rest hold seven eighths of it, and every executor holding one lets go of it at its next entry, so the open accounts stay within the budget plus one store's growth and the whole within twice it. The budget is a quarter of guest memory, at least 128 MiB and at most an eighth of the host's process memory limit: 2 GiB for an 8 GiB guest and 358 MiB for the iPad's 2 GiB guest. It is sized never to act on the measured workloads: a census at 4 KiB guest pages peaked on four vCPUs and 8 GiB at 68 MiB (single-core) and 74 MiB (multi-core) for arm64 Geekbench, 223 MiB for Aquarium and 296 MiB for x86 multi-core Geekbench, a seventh of 2 GiB, and at the iPad's geometry at 71 MiB for multi-core Geekbench and 133 to 168 MiB for Aquarium, 47% of 358 MiB at most, the least headroom; nothing was shed. Timing against the slot-count commit stayed level on the M4 MacBook Air and the iPad mini 6. Bound bytes directly, at a layer every engine's spaces charge, and size the bound from the measured workloads so that it only ever acts on a pathological one. |
| G283 | Index the arm64 gadget cache sets by a multiply | Measured; not built. X96 asks the same of arm64, whose set folds the instruction PC shifted right by two with the address space's number. A census at 262,144 slots counted the sets holding eight or more under the fold, under a multiply and for a uniform spread: Geekbench 6 multi-core 3,395, 3,482 and 3,557, a parallel gcc build 717, 559 and 675, WebGL Aquarium 9,341, 9,016 and 9,195. The fold is within 7% of a uniform spread in every count, where x86's was ten times it, and Aquarium's misses are first-time code, not conflicts. A set index is worth changing only where the resident sets load unevenly; recompute both indexes from a census first. |

## Host instructions per guest instruction

| Attempt | Disposition and lesson |
| --- | --- |
| Measure host instructions per guest instruction | Measured with per-carrier hardware counters and an exact execution histogram. Geekbench single-core costs about sixteen host instructions per guest instruction, almost all in gadget entries; memory transfers are a quarter of guest instructions but the largest share of fast-path cost, and a few hundred hot entries cover nearly every execution. It ranked the transfer and chain-exit work that followed. |
| Count why linked chains return to the executor | Measured. Most executor round trips are indirect-site misses, most of them returns, and most at sites with more targets than any small cell array can hold; each round trip costs a few hundred host instructions. This motivated the return-record ring and G220's target table. |
| Return-record ring for cached returns | Accepted, and unconditional. Linked calls push {return PC, return BlockLink} on a private sixteen-record ring, and a cached return whose cells miss pops a matching record and trains the cell, removing most return misses for a few percent on Geekbench and Aquarium; a deeper ring changed nothing. A first form that skipped cell training lost on monomorphic returns, so the ring must train the cell as the cold helper would. |
| Tagged TLB keys | Rejected, and its switch removed. Keying the software TLB by the address as presented removes the two-instruction top-byte check from every scalar transfer, but Geekbench single-core measured −1.2 percent score and +1.3 percent guest CPU time, and Aquarium −2.2 percent, none positive. As in G186 and G187, the check overlaps the TLB dependency chain rather than extending it; MTE guests would also key several tags of one page into the same set. |
| Fused transfer translation | Accepted, and unconditional. Keying same-page transfers by the page of the final byte while indexing by the first folds the cross-page check into the tag compare, since 16 KiB neighbours never share a direct-mapped set, and trims a few host instructions from every hit path for small Geekbench gains. The compare's operand form mattered: a shifted-operand `cmp` was slower than a separate shift and plain compare. With the count reduced, the remaining transfer lever is latency, not instruction count. |
| Four indirect cells and NOP elision | Four cells: removed; they cover only the minority of misses at three- and four-target sites. NOP elision: rejected, and its switch removed; leaving BTI and PAC hint entries out of the stream was level on a loader-like corpus and Geekbench, because a dispatched NOP is two predicted instructions that retire in the shadow of the gadgets around it. |

## x86-64 gadget engine campaign

Measured on macOS with matched ABBA runs: focused static x86-64 probes in the
guest for the mechanism, then Geekbench 6 single-core at one iteration, which
reproduces the default run's per-workload rates, for the workload. X1 through
X13 were settled together over the full suite; later entries were each
measured against their parent on the workloads their mechanism reaches.

| ID | Attempt | Disposition and lesson |
| --- | --- | --- |
| X1 | Declare the ARMv8.5-A host baseline | Accepted as an enabler with no performance claim. The engine is macOS-only, so every host implements LSE, FlagM, FlagM2 and FRINTTS; the assembled object is byte-identical. |
| X2 | Drop result normalization the host already performed | Accepted. A W-form host instruction writes the whole 64-bit register, so width normalization was a no-op at 32 and 64 bits. 32-bit register arithmetic improved 12%. |
| X3 | Fold away the page-crossing test for single-byte accesses | Accepted. A one-byte access cannot cross a page. Byte memory operations improved 4%, and forcing the check to emit reproduced the previous engine instruction for instruction. |
| X4 | Write the deferred-flag tail as one constant | Accepted. Operation and width are macro parameters and the rest of the tail is zero, so eight bytes are one link-time constant. Compare, set-condition and locked paths improved 4%. |
| X5 | Interprocedural optimization for the translation path | Accepted on workload evidence against probe evidence. Steady-state execution is 0.5% to 2.3% slower, but four Geekbench workloads gained up to 2.75% with none regressing. Probes cannot see a change that only affects translation. |
| X6 | Resolve effective addresses without branching on the descriptor | Accepted. Every address field is a translation-time constant. An always-zero state slot lets an absent base or index be added unconditionally and lets the segment selector index a table; truncation distributes over addition, so the narrow-address mask applies once to the sum. Eight branches become none, the bank loses 13%, and memory operations improved 2% to 12%. |
| X7 | Extract byte sign masks with NEON | Accepted. Four shift-and-accumulate steps replace a loop that ran once per lane. The instruction is 78% faster; it is the core of glibc's SSE2 string routines, which a static histogram of a dynamically linked benchmark cannot see. |
| X8 | Skip the store-side publication and overlap check | First attempts rejected: hoisting the check before the store, gating it on the write-code flag, and gating it on the executable-page bit all measured no gain, because Linux grants READ_IMPLIES_EXEC to binaries without a non-executable stack marking and every data page then qualifies as executable. |
| X8b | Call code publication only when a store can publish something | Accepted. Publication was over half of every guest store's cost, and its call is a lookup that misses whenever the page holds no cached translation; recording that in the write translation, and retiring the translation when a page gains code, turns it into one bit test and made stores about twice as fast. The expensive part of a sequence can be the call it guards rather than the instructions that are visible. |
| X9 | Evaluate branch conditions from the deferred record | Rejected. The premise was that a conditional branch pays full flag materialization, but that routine exits early and is already cheap; adding a pre-check ahead of it made conditional branches 57% slower in two independent implementations. |
| X10 | Fold the recorded operation and width into flag materialization | Accepted. Both keys are constants at the recording site, but the materializer rediscovered them through two run-time chains that reached the commonest cases last. One bounded table branch now selects a body with both folded in, so the width masks, the sign-bit index and the clear mask are immediates. INC 22% faster, SETcc and ADC 18%, CMP/Jcc 15%; File Compression +3.1%, PDF Renderer +3.1%, Horizon Detection +2.9%. |
| X11 | Discard the deferred record in the bit-count family | Accepted. TZCNT, LZCNT and POPCNT define every arithmetic flag and cleared all six immediately after paying to materialize them, and every override any gadget records lies inside that same clear mask. Two stores replace the call, and a TZCNT after an ADD is 69% faster. |
| X12 | Evaluate carry conditions from the deferred record | Rejected, reproducing X9 from the opposite direction. This version replaced the call instead of adding a check in front of it, and carry-condition branches were still 70% slower. The zero-condition shortcut it imitates works because a recorded result is already width-masked and one compare answers it; carry needs the recorded operation, so the shortcut reintroduces the dispatch it exists to avoid, in a gadget rather than in a shared routine. |
| X13 | Stop advertising ERMS | Accepted at the time, superseded by X15. While REP ran as a per-element loop, withholding ERMS moved glibc's string work onto the vector gadgets and gained several percent on string-heavy workloads. A capability claim is a scheduling hint to the guest's own dispatchers, so it is a performance decision as well as a compatibility one, and withdrawing a false claim is only one of the two ways to settle it. |
| X14 | Move a repeated string operation in page-bounded runs | Accepted. REP MOVS and REP STOS paid address resolution, a TLB probe and publication once per element; a run confined to one source page and one destination page now pays them once and moves 64-byte blocks, making byte-granular REP tens of times faster. The first version fell back to the element loop whenever the destination page could hold code, and gained nothing. |
| X15 | Advertise ERMS again | Accepted, superseding X13. Once X14 made REP a block move, REP MOVSB and STOSB outran glibc's SSE2 and AVX2 routines even at short sizes, and withholding ERMS no longer bought anything measurable, so the bit went back for the guests that assume it. |
| X16 | Keep the native chain alive across a code publication | Accepted, and the largest result of the campaign. A code publication reset every link in the address space, and links came back only on translation or on one revalidating hit path, so the engine left an already resident stream every few guest instructions. Re-arming a record whenever its slot is returned, and settling a publication when a run leaves the stream as well as when it follows a link, raised instructions per stream entry about sixfold and the three lowest-scoring workloads by 77 to 134 percent. Counting stream entries against retired instructions is what exposed it. |
| X17 | Materialize only the carry for the operations that need it | Accepted. INC, DEC, ADC and SBB called the full flag materializer although only CF is live; a carry-only entry through the same operation-and-width table serves the register forms, since a memory form can fault while the stale bits are still visible. Probes gained about 1.7x and workloads a few percent; the gap between the two is the operations' share of a real mix, which the probe alone could not settle. |
| X18 | Read a condition from the flags the compare already set | Accepted. After a 32- or 64-bit CMP, SUB, TEST or AND computed with the flag-setting host instruction, NZCV already holds the x86 flags, so the builder pairs such a producer with a condition consumer through one variant per condition; parity, the CF-consuming conditions after a logical operation and the narrow widths keep the deferred path, and the deferred record is still written so PUSHF and ADC stay correct. Workloads gained several percent while a probe of pure block transitions regressed: the probe measured the one thing the change does not address. |
| X19 | Advertise fast short REP MOVSB | Accepted. glibc reads FSRM separately from ERMS to send short copies to REP MOVSB, and after X14 that claim holds; the workloads neither gained nor lost. As in X15, the burden falls on withholding: a neutral measurement is no reason to route the guest around a path that is not slow. |
| X20 | Widen the indirect-branch site cache from two targets to four | Rejected. Four ways per indirect site sped a probe with four call sites into one callee but left the call-heavy workloads inside their spread, because sites that miss with two ways and hit with four are rare in real code. The mechanism working is not the same as the change paying, the gap X17 crossed in the other direction. |
| X21 | Keep a call in the stream when it publishes a code write | Accepted, and the largest result since X16. A per-site exit census found one instruction responsible for most of Geekbench's exits: a linked CALL leaving because its own return-address push had published a code write. A call now publishes and continues like any store, leaving only when the write lands inside the running block, which sped call probes up to 2.4x and the call-heavy workloads by nearly a fifth. A per-site exit census finds a cause that a per-category one cannot. |
| X22 | Link the block end the fetch window created | Accepted. A block cut short by the fetch window ended in an unlinked fall-through, the largest remaining exit cause; the next address is as static as a jump target, so a block that actually falls through now asks for a link, removing nearly all such exits. Clang, with much the largest code footprint, lost a little to the extra link record per truncated block and was outvoted by the other workloads. |
| X23 | Keep indirect-site training across a link cooling | Rejected. Retaining indirect-site training across a link cooling is safe, but the retained entry hits and then follows a dead link, so the exit still happens one category over; an exit census showed the total unchanged. Moving an exit between causes is not removing it, and a census of causes settles such a change without needing a quiet machine. |
| X24 | Key the indirect-branch tier on the target rather than on the branch | Accepted. A return site belongs to the call that reached it, so a function called from N places has N return targets competing at one site however many ways it has, which is why X20 failed; one direct-mapped tier keyed on the target and shared across the address space holds them all, each entry only a prediction that the follower checks against the guest RIP. Monomorphic shapes pay a few instructions for the hashed lookup, but real code outvotes the probe. |
| X25 | Retire only the translations a code change covers | Accepted. A code change anywhere cooled every link in the address space; replaying the code-change ranges a reader has not seen through the cache's selective retirement, and retiring everything only when the span cannot be described, cut the link exits of browser workloads. The first attempt put a `std::shared_mutex` on the translated code-write path and cost more than the change saved, because libc++'s notifies on every unlock and ten vCPUs serialize; a sequence-stamped lock-free ring replaced it. |
| X26 | Reopen the instruction window instead of leaving at it | Rejected. Checking for interrupts and code changes in the stream at each window checkpoint, instead of leaving, removed half the remaining exits but was flat on Geekbench and slower on Chromium, and the in-stream code-change test proved load-bearing. Exits are not fungible: the cheap window exits re-enter without revalidation, while the ones that remain miss the cache or cool links. |
| X27 | Publish a code write only where some executor caches code | Accepted. Geekbench single-core rose about nine percent, matching what the profile attributed to publication. The cost of an imprecise publication is not the publishing store but every executor's reaction to it. |
| X28 | Bake registers into a generated scalar bank and read host flags at every width | Accepted. A Python generator emits a register-baked scalar bank whose register offsets and bases are immediates, which the host can forward through as G196 found, and host NZCV at every width widens the fused producers. A probe gain must be scaled by the share of real run time it touches before it is a projection. |
| X29 | Record shifts and overlay multiplies instead of materializing | Accepted. The campaign then stood at 1.42 times FEX on the same kernel, short of the summed projections because each assumed halving work that turned out to be a fraction of the total; FEX still led where vector and memory-transfer cost, not flags, set the pace. |

Continuing the decode past a conditional branch puts its fall-through in the same stream, the arm64 engine's G162, which also speeds the taken shape because blocks grow, and it raised every Geekbench workload and the single-core score by nearly a fifth. |
| X34 | Bias the retirement counter by the dispatch budget | Accepted. Counting retirement from minus the dispatch budget makes each linked edge's budget test the sign of one addition, the arm64 engine's G180 inverted; a small probe gain with less gadget text and a neutral suite is worth keeping. |

| X42 | Keep AESKEYGENASSIST in the vector unit | Accepted. The probes understated the suite because a benchmark loop touches its pages in order while a real workload interleaves them with other data. |
| X45 | Park the carry INC and DEC preserve instead of settling it | Accepted. When the builder cannot see the carry's producer, INC and DEC now park the pending record in a carry slot with a pending bit instead of settling it, and only a reader of the carry through such a record computes it; a unit test drives every reader across widths and producers. | X46 | Carry host flags across a baked memory transfer | Accepted. The baked bank's loads, stores, PUSH and POP now leave NZCV intact (the tag test is an exclusive-or and a compare against zero, the store epilogue orders addresses by the sign of a difference, and miss tails save NZCV), so a fused condition reaches its consumer across them. | X47 | Fix the generated NaN without a branch | Rejected. Replacing the indefinite-NaN fix's rarely taken branch with a branch-free mask made every floating-point result slower. A branch whose body is skipped is not a cost to remove; it is what makes the body free. |
| X48 | Re-check the stack's own TLB entry | Accepted. | X50 | Forward vector results in the map2 and floating-point families too | Rejected. A mechanism worth its test in one family is not worth it in the next, and only the suite separates them. |

| X52 | Feed a vector memory operand from the baked address entry | Rejected. | X55 | Make the code-page registry's membership exact | Accepted as a correctness-of-performance fix. The code-page registry counted per hashed bit with a hash that keeps neighbours adjacent, so a run of code pages could mark a thread's stack as code; every push then published and every vCPU retranslated every block, losing nine tenths of its speed in one run in ten. An exact count per page behind the bit, striped over the word-sized lock, removed it. | X56 | Keep a cached translation across another vCPU's code change | Accepted as a correctness-of-performance fix, and the other half of X55. Validation discarded a cached program whenever the address space's code-change sequence had moved, which under legitimate fast publication meant every block on every other vCPU; taking each page stamp once, before the bytes it certifies, makes it a lower bound, so only a publication that touched the program's page invalidates it, while a moved mapping sequence or raised interrupt still abandon validation. | X57 | Publish a code change for every executable page a program stores into | Accepted as a correctness fix, and the loose end X56 named. | X61 | Fetch an instruction's bytes in one page-bounded window | Accepted. | X91 | Carry an ordinary x86 instruction's position in a word its gadget already reads | Accepted. An ordinary-bank gadget that can fault, trap or leave took the instruction's 64-bit address from a stream word of its own that only its cold exits read. It now carries a 10-bit position, the address less the block's start, in spare bits of its memory descriptor (whose three offsets shrank to ten bits) or of its operand word, and the exits add the context's program begin back; a five-byte direct CALL carries nothing, because the address it pushes is its own plus five. A block ends before an instruction 1024 bytes in, which the 64-instruction limit never reaches. Stream words over 13 Debian binaries and cc1 fell 5.4 percent and a single-core Clang run held 1.4 percent less cache; Geekbench 6 stayed level. Vector loads and stores ran 5 to 10 percent faster in probes and a memory CMOV 9 percent slower, which padding that gadget back to its old 64-byte phase undid. A word only a cold exit reads should be recomputed from the block wherever it sits; one gadget's alignment phase alone can move a probe by 9 percent. |
| X92 | Fold small x86 operands into the ordinary descriptor | Measured; not built. A census over the same binaries gave the ordinary bank's 16-bit displacement 0.4 to 0.8 percent of stream words, a register-immediate none, a shift, BT or IMUL count 0.2 to 0.3 percent and a vector immediate none, since the baked bank serves long mode; only compatibility-mode code, which is all ordinary, would save more. A displacement does not fit the descriptor without a gadget variant per memory shape or a conditional load, and an immediate extracted from an offset word costs an instruction in every execution, which G212 and X76 priced out. A fold has to pay in executed instructions as well as in words, and where the words are few nothing else decides it. |
| X93 | Leave a baked x86 PUSH and POP no stream word | Accepted. A baked PUSH or POP of a register read a stream word of its RIP and length that only its fault and overlap exits used. A cached block's PUSH and POP now carry none: those exits store the stream position, and the runtime finds the instruction by decoding the block's kept bytes again and locating the word where the builder would have put it. A stream built for one limited or checked run keeps the ordinary forms, and so does compatibility mode. Stream words over 13 Debian binaries and cc1 fell 2.9 percent and a single-core Clang run held 1.1 percent less cache. Baked stack faults are rare (11 of 5.0 million faults in a full Geekbench 6 run); the recovery costs about 0.3 microseconds for a short block, which a loop built to fault once per PUSH or POP shows as 17 and 25 percent slower per fault. A word only a cold exit reads can be dropped where the exit can recompute it from what the block keeps, at the price of that recomputation on every such exit. |
| X94 | Release the x86 link records and sites nothing names any more | Accepted, with arm64's G256, under the same rule. A released record's live-list entry is unlinked first, and a target-table entry naming it reverts to the vacant entry. At 262,144 slots, before X88's packed slots, multi-core Geekbench's records were all still named (four sweeps, 407 to 404 MiB); 131,072 slots were not measured on x86. The lesson is G256's. |
| X95 | Let go of the x86 gadget spaces of address spaces the kernel destroyed | Accepted, with arm64's G272, under the same rule. An x86 executor's cache is private, so the executor that ran a destroyed generation holds all of its translations, link records and indirect sites. `run_x86_gadgets` gives each executor the MMU's count of destroyed generations and its answer for a generation (an injected function, so the executor reaches the MMU through no new edge) at the start of every run; one whose count moved lets go of each address space reported destroyed, releasing its code-page registries, and keeps a tombstone in the window's order. If the space just prepared is among them, the cache prepares again. In a Geekbench 6 multi-core census the cache averaged about 4% less and held 7 to 10 MiB of dead spaces before and none after, at an unchanged hit rate; scores stayed inside the runs' spread. |
| X96 | Index the x86 gadget cache sets by one multiply of the key | Accepted. The set came from two xor folds of the byte-granular RIP, the generation and the mode. Guest code clusters at alignments and strides, a fold is linear, and keys that differ by a multiple of its kernel share a set whatever else they hold: a parallel cc1 build left 1,179 resident sets full where a uniform spread has 128, and 85.4% of its 28.0 million stores were of a translation the cache had already evicted at 30% occupancy. The set is now the top bits of the key times a 64-bit constant, one multiply and a shift replacing the two folds and the mask. At 262,144 slots the cc1 build's stores fell from 27.97 to 4.24 million and its hit rate rose from 97.63% to 99.63%; Geekbench 6 multi-core stores fell from 1.68 to 0.96 million, so the cache keeps what it no longer evicts and grows by at most 7%. Twelve cc1 compiles ran 2.4% to 3.9% faster and Geekbench 6 stayed level. One multiply is the cheapest index that spreads measured code like a uniform one. Judge an index by recomputing both from a census of the resident keys, not by the hit rate alone. |
| X97 | Keep an x86 translation in an arena body that its address space's Space owns | Accepted, as the groundwork for sharing translations among an address space's executors (X98); the arm64 engine's sharing machinery moved to `darwin/cpu/` unchanged first. A cached translation was three allocations, a record, its native stream and its saved source, each charged to the budget as the allocator sized it. It is now a 128-byte body in a `BodyArena` with its stream directly behind it and its guest bounds in front, the source cold in a second arena so streams stay dense, and a slot keeps the tag, the body and a few words; the arenas, link records, indirect sites and target tables of an address space are its `Space`, owned by one executor. Nothing is shared, and what the step must not change stayed level: a Geekbench 6 multi-core cache held 3.4 percent more at its largest snapshot at an equal hit rate, and scores were level. A restructuring that moves where state lives is accepted on what it must leave level, bytes, hit rate and score. |
| X98 | Share an x86 address space's translations among the executors that run it | Accepted, behind `DARWIN_UML_GADGET_SHARED_BODIES=1` until X99. The four vCPUs of a Geekbench 6 multi-core process each translated and kept the same code, so one run's cache peaked at 377 MiB. Executors of one address space (one generation, the same exceptions enabled) now share a `Space`: the bodies, link records, indirect sites, target tables and a page index. A lookup that misses in an executor's slots takes the body from the space, validates it as a stale slot is and slots it with no copy; a link is one aligned pair that a single paired store retargets (FEAT_LSE2), so an executor follows a link another armed. A store marks every overlapping body stale for all and a build pins the pages it reads, so a build that raced a store is not kept; a body let go of waits in limbo until every executor seen inside translated code has left. In a Geekbench 6 multi-core census the cache peak fell from 377 to 151 MiB (-60 percent) and stores from 0.96 to 0.32 million, with scores level. A cache that holds what its siblings hold costs the union of their code, not the sum; what that needs is a store protocol on every code page a body reads, which the unit tests break on purpose. |
| X99 | Renew a shared x86 address space once its arena is mostly freed, and share by default | Accepted. A private address space is swept by its executor, which reads that executor's slots; a shared one is never swept, so under process churn its arenas kept the holes that freed bodies left. A shared `Space` now counts what its arenas hold against what the bodies some slot holds take of them, and once the arenas hold at least as much freed space as bodies and at least 2 MiB it is closed: it leaves the registry, every executor attached lets go of it before it next enters translated code, and the next executor to want the address space gets a new one. A cache checks after the store that publishes a body and when it lets go of a space whole; the byte budget closes a space the same way when it sheds it. Freed blocks that a new body fits are reused, so steady churn of equal blocks renews nothing. Sharing is then the default, `DARWIN_UML_GADGET_SHARED_BODIES=0` keeping each executor's translations to itself. The unit tests carry the proof of bounded growth, because Geekbench's processes end before their arenas fragment; timing was level, apart from three Mac-pool series that read sharing's multi-core 1 to 2 percent low and a fourth on the merged tip that did not reproduce it. A bound a cache cannot reach is no bound: the first check of the retire path survived its mutation until the test made a space idle before the cache let it go. |
| X100 | Replace an occupied entry of a shared x86 target table one time in eight | Measured; not built. A census counter build writes a four-vCPU Geekbench 6 multi-core run's target tables 286 million times private and 462 million shared, each a trained entry that differed from the one held, and a shared table's lines may be traded between cores. A throttle in one binary, replacing an occupied entry one attempt in eight, ran multi-core 349 against 341, the one run that lost 15 percent being at a host load of 12.7; without it the arms read 349 against 347. A write count is not a cost until a same-binary switch moves the score, and this one did not. |

The opening profile ranked candidates by what executes rather than by a static
instruction histogram, and so retired several planned items that barely ran:
truncating FP conversion and scalar FP compare, locked read-modify-write,
gadget-TLB associativity, and specialized shifts and stack fusion. Its largest
item, leaving and re-entering the stream, was not answered by any of the
structures the plan proposed; counting exits by cause found the existing chain
machinery switched off wholesale (X16), and later exit censuses drove X21 to
X26. What remains of stream re-entry is exits that miss the program cache or
re-arm a cooled link, so further work belongs in translation and validation
rather than in the count of returns.

Five lessons generalize. Whether a page might hold code is not a condition this
engine can branch on to save work. An executable-stack declaration has Linux
mark every data page executable, and a probe whose data segment is plain
read-write with a non-executable stack still reported code-capable on every run,
while across the workloads publication actually fires on well under one percent
of self time. The predicate is true far more often than publication is needed
and cannot be predicted from the guest's own markings, so X8's first attempts
and X14's first version both measured nothing by skipping work when it was set.
The work has to become cheaper rather than conditional. Instruction count
inside a gadget is a weak predictor: the changes that paid removed a loop, a
call, or a branch, and those that only shortened a straight-line body did not.
A probe measures the mechanism it names and nothing else, so a candidate that
only affects translation, or that trades throughput for latency, needs a
workload to judge it. And laziness is worth paying for only where retrieving
the deferred value is cheaper than computing it: X9 and X12 failed at the same
boundary from opposite directions, while X10 succeeded by making the deferred
path itself cheaper rather than trying to avoid it. Finally, a profile ranks
what runs but not how often a structure is bypassed; where a fast path exists,
count how often it is taken before assuming its cost is the thing to reduce.

## x86 equality conditions in Wine

| Attempt | Disposition and lesson |
| --- | --- |
| Avoid full flag evaluation for equality-only consumers | Accepted. Register CMOVE and CMOVNE read the deferred zero result while keeping the other pending flags, and adjacent 8- and 16-bit CMP, SUB, TEST and AND consumers reuse the host zero flag, with differential tests preserving the full later flag result. It removed startup work from a timed game launch, which stayed close to its deadline, so it is not a reliability or general speedup claim. |

measured against a same-day control, gadget changes on the iPad and JIT changes
on the Mac, and landed only when every probe and workload was neutral or faster.

| Attempt | Disposition and lesson |
| --- | --- |
| Remove the gadget body arena's counting resource | Rejected. The wrapper's only reader had moved to the arena's own count, but it is `ProgramCache`'s first member, and removing it shifted every member's cache-line phase and slowed the bimodal indirect-link probe. The member stays; a dead member at the head of a page-aligned hot structure is layout, not dead code. |
| Drop `ProgramWords`' zero-length inline buffer | Rejected. ## AArch32 JIT: memory access

Inline TLB probes are 20% to 40% of the host instructions executed in the
memory-heavy single-core workloads, so a shorter probe is a general saving.

| Attempt | Disposition and lesson |
| --- | --- |
| Probe the 4 KiB TLB in two fewer instructions, skip the crossing test of an access aligned to its size, and fold the crossing test into the tag compare | Accepted as three changes with one measurement: single-core +5.6% over the block before them, 11 of the 12 workloads level or faster (Machine Learning 1.14, Gaussian Blur 1.11). The A32 probe is its own copy of the shared sequence: bit i of the index is bit 12+i of the address xor bit 25+i, which is one xor with the address shifted by 13 and one extract, and the tag compare shifts the address itself. Comparing the tag with the page of the last byte makes the crossing test free, because the entry belongs to another page when the access crosses; an access aligned to its size cannot cross. The tests compare the emitted words, because a probe with a wrong index passes every behavioral test by missing. |
| Keep the exclusive monitor across ordinary stores (A64 and A32) | Accepted as a correctness fix. Clearing the monitor at every store, as the architecture permits, made a spill between a LDREX and its STREX fail the pair on every retry: ART's card-table update stores a register pair there, and the 32-bit zygote's collector spun forever on the JIT. Hardware keeps the monitor across a store to another granule, so the JIT now clears only where a pair ends and relies on the reservation versions for the rest: a store to the reserved granule, the reserving vCPU's own included, fails the store-exclusive. In the AArch32 workloads the clears were 0.5% to 1.3% of the executed host instructions. Measured on the JIT, the A64 Geekbench 6 single-core subset executes 1.3% fewer host instructions and scores level to slightly faster, the store-heavy and exclusive probes are level within 3%, and a ten-vCPU Android boot is level within its run-to-run spread of 20%. What the fix keeps paying is the tracked store variants, which every vCPU runs while any vCPU holds a reservation: 16% of the store-publishing block entries of that boot, 79% of a four-worker probe built to hold one, none of a single-core Geekbench run. A reservation that is never consumed is rare (0.4% outlive the executor's run, 0.3% are replaced by a later load-exclusive) and none lasted a second. |
| Add the TLB delta in the access, as `[x9, w8, uxtw]`, instead of before it | Accepted. The add was 2.8% to 5.1% of the executed host instructions and three quarters of the accesses after it have the register-offset form. Single-core +4.8% over the step before it together with the revert of the skip region below (Speech Recognition 1.16, Camera 1.12, Text Compression 1.05). A pair, a multiple transfer, an acquire or release, a lane transfer and a store that records its host range keep the add. |

## AArch32 JIT: blocks, links and registers

| Attempt | Disposition and lesson |
| --- | --- |
| Go on past a conditional forward branch (B, CBZ, CBNZ) in a block, with a cold side exit for the taken path | Accepted. Every conditional branch had ended a block with two links, so the short blocks of the benchmarks paid a link sequence and the loads of the next block on every transition. Single-core +9% (Text Compression 1.06, SQLite 1.09, N-Body 1.03, Face Detection 1.02). |
| Run a block that branches back to itself as a host loop | Accepted. A probe compilation records the registers the body holds, the loop loads them once and the back edge publishes only the flags and checks the budget. Single-core +2.2% with Machine Learning +13%, measured on a loaded host. |
| Hold the loop's most used registers, not its first | Superseded. Neutral alone (1.004) and made moot when a translation took all fifteen core registers. |
| Keep the target of a forward branch in the block, over the instructions it skips | Rejected and reverted: 0.996 of the block before it. It carried the most state in the compiler (a second set of bindings and flag states for the skipping arm, a join that reconciles them, a retry that compiles the block again without a region that does not fit, a budget credit for the skipped instructions) and the cold side exit it avoids costs one link. It also made reachable a latent defect, which the revert makes unreachable again: a cold path stores the dirty registers through the bindings at the end of the block, which is wrong once a binding is forgotten in the middle of one. |
| State the loaded FP state and the native environment in every chain's link selector | Accepted. A chain's selector described its first block, so a loop of an integer block that stores and a block of Neon arithmetic returned to the executor at both edges of every iteration: two blocks made 160 of Structure from Motion's 240 million returns. Returns fell from 247 to 64 million. |
| Look up an indirect branch's target in a per-executor table behind its two cells | Accepted. A return from a function with more than two callers cannot keep its targets in two cells (libm's `lroundf` from four places made 36 million returns in Structure from Motion). A 4096-entry direct-mapped table of trained targets takes the third level, tagged with the link epoch because it outlives address spaces: the first version without the tag followed another address space's function at the same address and killed init, which the userspace smoke found. Returns fell from 64 to 19 million in Structure from Motion; together with the selector row, single-core +10% (SQLite 1.35). |
| Hold all fifteen core registers in the host (x22 to x28 beside the eight) | Accepted, small on its own: single-core +0.7% (Structure from Motion +2.4%). A block that names r0 to r12 did 25 register-file accesses per pass with eight host registers. It is the precondition of the next row. |
| Keep the core registers in the host across links | Accepted. A linked translation loads the fifteen registers once, before the internal entry that only the executor reaches, a link leaves them in their hosts and only a return to the executor writes them back, in pairs. Single-core +4.1% over the step before it (SQLite 1.13). Registers the link sequence had used as scratch (x12 and x13) became resident, and two conversion lowerings that used the hosts of r0 to r2 as scratch became a defect that the change exposed: a kept register set turns every hard-coded scratch register into one, so the tests write r0 to r2 before the instructions that use scratch. |
| Go on past a conditional branch back | Accepted. A loop body that tests its bounds with several branches back to the loop's increment was a chain of two-to-four-instruction blocks that fall through nearly always, each paying a link. Horizon Detection +3.2%, Speech Recognition +3.9%. A branch back to the block's own first instruction still ends it, for the host loop. |

## AArch32 JIT: candidates not built

| Attempt | Disposition and lesson |
| --- | --- |
| Cache the last page ahead of the TLB probe | Rejected before building. The crossing test an access needs beside the cached page compare costs what the cache saves. |
| Keep the vector registers in the host across links as the core registers are | Not built. Vector spills and fills are 2% to 6% of the executed host instructions in the floating-point workloads, an expected 1% of the single-core score, for a fixed binding of the A64 compiler's dynamic vector residency and every helper that reads the vectors. |
| Fold the alignment test into the tag compare | Not built. The alignment test is 0.2% to 1.9% of the executed host instructions (5.2% in N-Body), not a gain a paired run resolves. |

## AArch32: AES-XTS and Face Detection

With the JIT at 0.89 of aarch64 single-core on the M1, AES-XTS (0.26) and
Face Detection (0.34) were the lowest Geekbench 5 armv7 workloads. Each JIT
row compares concurrent pairs of 1-vCPU guests on the M1 Ultra against the
commit before it. Over the three accepted rows the armv7 single-core score rose
1.08 (Face Detection 2.50, Camera 1.37, Horizon Detection 1.32), an estimated
0.85 of aarch64 for Face Detection and 0.97 for the single-core score. The
aarch64 emission is unchanged.

| Attempt | Disposition and lesson |
| --- | --- |
| AES-XTS in either engine | Intrinsic; nothing changed. The armv7 binary holds no AESE, AESD, AESMC, AESIMC or VMULL.P64 in either instruction set, although the guest advertises the AArch32 crypto extension and OpenSSL in the armhf guest uses it. Geekbench encrypts with lookup tables, 11 to 19 times the guest instructions that the aarch64 build's AES instructions need, and both engines retire those instructions at least as fast as aarch64 ones (ratio 0.26 in the JIT, 0.07 in the gadget engine, which runs aarch64 AES as fast as the JIT). Count the instructions per unit of work of the two binaries before looking for an engine cause. |
| Face Detection in the gadget engine | Nothing specific to armv7: 0.77 of aarch64. The gadget engine addresses each S register in CpuState, so the lane inserts of the JIT rows below do not arise there. |
| Convert singles to and from integers in the vector unit (JIT) | Accepted. VCVT between a single and a 32-bit integer went through W0 twice; the A64 scalar SIMD forms round, saturate and raise the flags as the general-register forms do. Face Detection 1.41, Camera 1.22, Structure from Motion 1.16, Horizon Detection 1.11, Speech Recognition level. The AArch32 corpus could not tell FCVTZS from FCVTNS, because no conversion input had a fraction; its simd-convert suite now has them. |
| Keep S registers in V registers through runs of VFP instructions (JIT) | Accepted. An S register is a lane of its resident Q register, so every single-precision instruction moved its operands out of their lanes and inserted its result, and an insert rewrites the whole Q: Face Detection's four independent chains on S8, S10, S12 and S14 (lanes of Q2 and Q3) waited for each other's inserts. In a run of unconditional single-precision instructions an S register now keeps a copy in a low V register that later reads take; an instruction that may write an S register another way or use those registers forgets the copies. Face Detection 1.70, Horizon Detection 1.19, Camera 1.12. Lanes packed into one register serialize independent work through their inserts; a copy outside the packing removes the dependency. |
| Let an A32 block hold all 64 instructions (JIT) | Accepted. The 60-instruction target leaves room for an IT block that a block's last instruction opens, which only T32 has. Face Detection's feature loop ran a block of 60 and a block of the four instructions after it on every pass; one block of 64 saves a link: Face Detection 1.04 (nine of ten pairs), the other workloads within 1%. |
| Link a loop block's exit through the unconditional B after it (JIT) | Not built. Face Detection's inner loop leaves into a one-instruction block, a B to the outer loop's head, on every pass; the row above puts one link at about 4% of that workload, but the change reaches into the host loop's exits, budget and saved guest words. |
| Cache the TLB page for a run of table loads | Not built. After the rows above, TLB probes are 38% of the host instructions in Face Detection's loop and 57% in AES-XTS's table rounds, but a translation holds all fifteen core registers, which leaves no host register for a cached page, and the last-page cache above was rejected for the crossing test it needs. |

## AArch32 gadgets against the Raspberry Pi 4

Each row runs Geekbench 5 armv7 single-core in the gadget engine on the M1
Ultra against the commit before it. The engine's gap is its armv7/aarch64
ratio divided by the same ratio on a native Raspberry Pi 4 (Cortex-A72). At
the start it was 0.85 for the single-core score, with Gaussian Blur at 0.57
and Machine Learning 0.59; after the accepted rows it was 0.87, with Gaussian
Blur at 0.66 and Machine Learning 0.63.

| ID | Attempt | Disposition and lesson |
| --- | --- | --- |
| G242 | AES-XTS against the Pi 4 | Measured; nothing to change. The Pi 4's Cortex-A72 has no AES instructions, so both of its builds encrypt with tables and armv7 reaches 0.84 of aarch64 there. Our 0.07 measures the host AES instructions our aarch64 guest runs, not a slow armv7 path. The armv7 rounds are 47 percent table loads through the TLB probe, which G243 shortens for every load. |
| G243 | Key the 4 KiB AArch32 TLB probe by the access's last byte | Accepted. The folded 4 KiB index puts pages n and n + 1 in one set only when n has 25 trailing ones, which no 32-bit page number has. The crossing test therefore joins the tag compare as it does on 16 KiB, and the set index takes one xor and one extract: 9 probe instructions instead of 12 for each multi-byte access. Single-core +3.1 percent with 18 of 21 workloads higher (Structure from Motion +5.9, Camera +5.3, Navigation +4.4, Gaussian Blur +4.2). A wrong set index only shows as misses that the C++ fill path hides, so the control test fills an entry through that path and must hit it through the emitted probe. |
| G244 | Run conditional data processing that sets no flags as a select | Accepted. A conditional instruction went behind a skip gadget whose branch follows the guest's condition, which the image kernels compute from their data, so the host mispredicted it: skips took 4.5 to 6.9 percent of the timed samples of Image Compression, Ray Tracing, Speech Recognition, Navigation and Face Detection. MOV, MVN, ADD, SUB, RSB, AND, ORR, EOR and BIC of an immediate or a register, and MOVW, now look the condition up in a truth table over NZCV and select the result or the old value. Face Detection +6.4 percent, Image Compression +2.7 to +3.6; the single-core score was level. A branch on guest data costs more than the work it skips. |
| G245 | Run the ADD or SUB that computes a VLD1 or VST1 copy's base inside the copy | Accepted. Gaussian Blur computes each copy's address with an ADD of an immediate, mostly with Advanced SIMD arithmetic between, 17 of every 100 instructions. The copy's gadget now does the ADD and writes its register before the transfer, and the ADD's words leave the stream. Only unconditional Advanced SIMD data processing that reads no core register may come between, which cannot exit or fault, so every exit sees the state the instructions in order leave; the corpus's `sequences` suite checks the faulting, wrapping and separated shapes. Gaussian Blur +13.7 percent, Face Detection +2.5, Speech Recognition +2.1. |
| G246 | Give hinted VLD1 and VST1 copies and VLD1 to all lanes their own gadgets | Accepted. Machine Learning's loop copies with a 128-bit alignment hint and loads to all lanes, both through the general structure gadget and its dozen tests. The new gadgets take the alignment mask in their operand word and leave a misaligned access to the library, whose fault order it owns. Machine Learning +4.8 percent (all pairs), single-core +1.5 (four pairs higher, none lower). |
| G247 | Fuse VCMP and the VMRS APSR_nzcv after it | Accepted. Ray Tracing and Speech Recognition compare floats and move the flags to the core at once, 3.2 and 1.75 times per 100 instructions. The compare's gadget is rewritten to the fused one, which sets FPSCR's flags and NZCV in one dispatch. Ray Tracing +2.5 percent (all pairs), Speech Recognition +1.2, single-core level. |
| G248 | Run a conditional VMOV between VFP registers as a select | Accepted, small. Ray Tracing's conditional VMOV of D registers went behind a skip like any other conditional instruction; FCSEL copies the bits without raising anything, so the select needs no environment. Ray Tracing +1.0 to +1.5 percent (five of six pairs in both series), single-core level. Text Rendering and Navigation, which have no conditional VMOV, read about 1 percent lower in three and four of six pairs. |
| G249 | Let an A32 block hold all 64 instructions | Accepted, small. The translator stopped every block five instructions short of its window so that an IT block it started could complete, which only T32 needs; Gaussian Blur's and Speech Recognition's loops ran as blocks of 59. An A32 block now holds 64, a bound (`a32::block_limit`) that gadget words carrying an instruction's position may rely on. Speech Recognition +1.8 percent, Text Rendering +2.5, HTML5 +2.1, single-core +0.7. N-Body read 2 percent lower, but a same-binary switch and a layout control each moved it by less than 1 percent. |
| G250 | Fuse the dependent VMUL and VADD chains of Gaussian Blur and Machine Learning | Not built. After G243 to G249, the quad-register VMUL and VADD gadgets are 38 percent of Gaussian Blur's timed samples and 26 percent of Machine Learning's, and VORR copies another 10 percent of the latter. Each gadget reloads from CpuState the register the one before it stored. A gadget for a pair saves a dispatch and a reload, but needs one for each pairing of operations and shapes. |

## AArch32 gadget stream size

Each row shrinks what the AArch32 gadget builder stores per instruction.
Stream words come from a static sweep that translates Geekbench 5 armv7, the
Debian armhf release's /usr and eleven F-Droid armeabi-v7a apps without
running them; cache memory from a census of Geekbench 5 armv7 single-core at
131,072 slots with eight ways; timing is Geekbench 5 armv7 against the commit
before each row. Together G251 to G254 took 16.6 percent of the A32 stream
words and 16.2 percent of the T32 ones, and 8.2 percent of the single-core
cache at an equal hit rate; G259 to G261 took a further 3.0 percent of the
A32 words and 2.4 percent of the T32 ones. Both sets ran Geekbench 5
single-core level to 0.8 percent faster than main and leave the AArch64
gadget parts byte-identical.

| ID | Attempt | Disposition and lesson |
| --- | --- | --- |
| G251 | Fold a PC register operand into the immediate form | Accepted. PC as an unshifted register operand is a constant: the second operand of any data-processing instruction, the first of one that commutes, SUB and RSB swapping, and the base of [PC, Rm]. The builder emits the immediate or offset form with the PC value instead of a three-word scratch write. A fold whose other operand is its destination, as in position-independent code's `add rX, pc, rX`, takes the indexed immediate entry rather than G196's in-place one, because an indexed load writes the literal it adds to and indexed loads consume the sum: through the in-place entry AES-XTS ran 4 percent slower than before the fold, through the indexed entry 2.1 percent faster. Stream words -2.5 percent in A32 and -3.4 in T32; Geekbench 5 level. A fold that reaches a specialised entry inherits that entry's assumptions about its neighbours. |
| G252 | Take a linked call's LR from its return link | Accepted. A BL or BLX whose return address is linked follows that link, and the link's key is the return address with the instruction set in bit 62, so the linked and cached call gadgets derive LR from it and the builder drops the LR word from those forms; the unlinked forms keep it. Stream words -2.3 percent in A32 and T32 and the single-core cache streams -1.7 percent at an equal hit rate; Geekbench 5 level. |
| G253 | Let the memory transfers carry a position instead of a key | Accepted. The single and doubleword transfers, VLDR, VSTR, TBB and TBH pushed their instruction's key only so that a fault could name the instruction; like the exclusive and ordered gadgets, they now carry its position in the block in their operand word, and a fault reports the position, which the executor resolves to the key. Stream words -12.3 percent in A32 and -11.0 in T32 and the single-core cache streams -12.1 percent at an equal hit rate; Geekbench 5 level. A word kept only for a fault costs every translation that holds it; the position a fault needs fits in spare operand bits. |
| G254 | Fold a MOVT into the MOVW before it | Accepted, small. A MOVT right after an unconditional MOVW of the same register outside an IT block replaces the top half of the MOVW's constant, so the pair is one move of the whole constant and the MOVT's gadget and operand leave the stream. Stream words -0.12 percent in A32 and -0.18 in T32: the pair is rare in this code, which loads most constants from literal pools. Geekbench 5 level. |
| G255 | Recompute a block transfer's library operand instead of storing it | Not built. The semantic-library operand that LDM and STM carry for the page-crossing path is about 0.7 percent of A32 stream words and 0.8 of T32, and that of VLDM, VSTM and the Advanced SIMD structure transfers 0.3 and 0.45 more. The library could rebuild it from the instruction word, but reaching that word at run time means finding the block's body from the stream position or fetching the guest word by a key the gadget no longer carries, which couples the library to the program cache. Under one percent of the stream does not pay for that coupling. |
| G259 | Let the block transfers carry a position instead of a key | Accepted. LDM, STM, PUSH and POP pushed their instruction's key for a fault and for the semantic-library call of a transfer that crosses a page. They now carry their position in the block in the first operand word, as G253's transfers do, and the crossing path passes the position in place of the key: the library, told the instruction set by a bit of its operand, runs the instruction at address 0, since no block transfer the gadgets run reads its own address (an STM that stores the PC does, so it goes to the library with its key). Stream words -0.9 percent in A32 and -1.0 in T32. Ray Tracing lost 3 percent, which a never-run 384-byte pad that moves the later A32 gadgets as the change does reproduces: a loss in one workload, spread over gadgets the change does not touch, points to a layout shift before a code cost. |
| G260 | Pack a block transfer's registers five bits each | Accepted. The registers were CpuState byte offsets, eight to a stream word after the first operand word. Each is now its offset over four in five bits, which the access scales back: six fit beside the base and the position in the first word and the rest in one more, so every block transfer carries one word less. Stream words -0.8 percent in A32 and -0.9 in T32 at an equal hit rate; Geekbench 5 level. A scaled register index costs a load or store nothing over a byte offset. |
| G261 | Hold a short skip's distance in the gadget | Accepted. A skip read the byte distance over its run from an operand word. Each condition now also has a skip for every run of two to nine words with the distance as an immediate, 112 gadgets in all, and the builder takes one when it closes such a run, drops the operand and moves down the stream positions it recorded past it. After G244 turned most conditional data processing into selects, two-word runs were still 87 percent of A32 skips, and the baked range holds 99.5 percent of A32 skips and 93 of T32. Stream words -1.4 percent in A32 and -0.5 in T32 at an equal hit rate. A builder that removes a word from a stream under construction must move every index it recorded past it. |
