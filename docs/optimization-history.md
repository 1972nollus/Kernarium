# Optimization history

This is the repository's single history of attempted performance work. Entries
retain only the hypothesis, disposition, and durable lesson. They do not define
current behavior; current contracts live in architecture and subsystem docs.

`Accepted` means the useful mechanism remains or its result became product
policy. `Rejected` means the candidate was removed or disabled. `Measured`
means the work improved understanding without justifying a product change.

## General gadget forwarding

| Attempt | Disposition and lesson |
| --- | --- |
| Template-owned adjacent scalar result forwarding | Accepted as the default policy; `BuildOptions` can still disable it per program for controls. Shared assembly operand contracts select a forwarding variant from the decoded entry rather than from an opcode-pair whitelist. Dependent scalar probes ran two to three times faster while full workloads showed broad coverage rather than a general speedup, and a mechanism control must match both the code layout and the data addresses of its arm. |
| Template-owned adjacent SIMD/FP result forwarding | Accepted as a default beside scalar forwarding. Natural-v2 contracts extend the shared SIMD/FP templates without new hot-path producer copies. Geekbench gains were small against shared-host variation, so correct forwarding coverage is not a broad speedup claim. |
| Combined scalar/SIMD dependency coverage | Measured with both policies enabled. Broad contract coverage did not imply frequent adjacent dependencies: SIMD added only a few points of entered-instruction coverage. Coverage counts execution-weighted opportunities, not retired reads or speedup; the diagnostic was later removed (80e8e201). |
| Preserve results across opposite-domain gadgets | Measured, not enabled. Preserving results across audited nonclobbering opposite-domain entries added about a tenth of a point of coverage, too little to justify separate preservation contracts. |

| G189 | Mirror the retained arm64 cache hierarchy in x86 gadgets | Accepted after desktop-boot profiling and cache A/Bs: bounded four-way program storage, a two-way successor tier, and direct and indirect links reduced dispatch work without weakening exact source validation. |
| G190 | Bulk-own x86 cache-generation allocations and reuse validation buffers | Rejected; matched desktop boots were neutral to slightly slower. |
| G191 | Inline exact validation for tiny x86 source spans | Accepted; more than 90 percent of profiled validations were at most 32 bytes, and the change reduced full smoke-boot time by about five percent while the earlier queue milestone remained neutral. |
| G192 | Measure realistic scalar and SIMD gadget ceilings | Measured. A browser-like scalar mix and an FP inner loop with no exits ran far below the dependent ADD chain's ceiling, and a one-vCPU guest reached most of each ideal. The engine spends about four host cycles per realistic scalar word, so the ADD-chain ceiling overstates the reachable ratio several times over; the SIMD guest's wider gap points at the FP-environment work at each executor round trip. |
| G193 | Attribute the realistic ceiling cost with hardware counters | Measured with hardware counters. Threaded dispatch costs about 1.4 cycles a gadget and a block-link follow several more, while a result round trip through CpuState costs far more than a register; above the dispatch floor the mixes are bound by exposed dependency latency and misprediction refill, not instruction count. A reduction pays only when it shortens a chain on the critical path, by fusing dependent pairs or keeping a result live across more than one gadget. |
| G194 | Keep write-through results in a bank of forwarding slots instead of one adjacent register | Rejected at one and two slots. Forwarding slots that outlive intervening entries left the ideal ceilings unmoved, because the values the mixes wait on are loop-carried across block links where every slot dies, and the extra variant text cost the browser workload. The hops that bound a short block sit at its entry, so only residency that survives a direct link could remove them; diffing every entry's disassembly against the control under a register renaming found a hard-coded result register the unit fuzz had missed. |
| G195 | Reorder a block's instructions before translation so consumers follow producers | Rejected at both levels and removed. A list scheduler that moved consumers behind producers slowed the probes, Geekbench and above all Clang, where the scheduler itself was a large share of the run; the Aquarium stall it exposed was a kernel `line_throttle()` defect, fixed separately. The host core already overlaps independent chains across gadgets, so ordering is not a lever for a data-only engine, hop count is; an idiom-folding decoder must see only guest successors, and a hoisted instruction must not clobber an input that a faulting crossed instruction re-executes. |
| G196 | Address an in-place gadget's CpuState slot by a baked displacement instead of a decoded register index | Accepted; built together with G199 and G200. A dependent store-to-load pair through CpuState costs about 2.5 host cycles with a base-plus-displacement address and 6.8 with a base-plus-index one, because the core forwards at rename only in the first form, and unlike a forwarded register this survives block links and executor round trips. Baking a displacement costs one entry per guest register, so only the in-place shape, whose destination is also a source, is affordable. The addressing form of a CpuState hop, not its instruction count, decides whether the host can forward it; the SIMD three-same entries stay unbaked because their bank cost has not been shown to pay. |
| G197 | Give a template byte-identical copies so independent guest registers do not share one load and store program counter | Rejected, and the copies removed. Byte-identical copies of an entry give independent chains separate program counters for the host's memory-dependence predictor, which sped dense interleaved probes but moved realistic mixes and Geekbench slightly down. Duplicated entry text is charged to every workload, while several independent chains through one template inside the predictor's window is rare in real code. |
| G198 | Repeat the in-place displacement measurement on a second core generation | Measured on an A15 iPad. The in-place displacement gain transfers with a similar Geekbench mean but a different composition, and bank growth costs the A15 about a tenth of what it costs the M1. Rename-time forwarding through a constant displacement is not an M1 peculiarity, but a single dependent chain exposes it only on the M1, so the interleaved-chain probe is the one to trust across cores. |
| G199 | Bake the transferred register of a scalar memory transfer as a CpuState displacement, extending the in-place shape from arithmetic to memory | Accepted with G200; the in-place memory and immediate entries are always built together. Baking the transferred register rather than the base of unsigned-offset scalar transfers is the affordable choice, because a loaded value is consumed soon while a base is usually long-lived. A CpuState hop must have the same addressing form at both ends: a baked producer feeding an indexed consumer ran slower than a wholly unbaked engine. A large probe gain on a form that covers little of a real mix reaches workloads as nothing while its bank growth is charged to all of them. |
| G200 | Keep a baked family's cold tails out of its hot path so the copies cost only what differs | Accepted; it is what makes G196 and G199 default-on. Moving a baked family's TLB-miss and page-crossing tails into their own section, reached through one-word trampolines, cut the family's hot bank growth by more than half and turned G199's workload loss into a gain, largest on Clang. Measure a per-register family by its hot bytes rather than its total; the cost G194, G196 and X22 charged to large code footprints was mostly code those workloads never execute. |
| G201 | Store a gadget translation as one exact-sized allocation instead of a pooled body with a doubling stream | Accepted. Pooled bodies and doubling stream storage left the caches holding more slack than programs; one exact-sized, sixteen-byte-classed allocation per program with its validation words shrank the caches and peak RSS substantially, and every guest probe was neutral or faster. A translation cache's allocator is part of its footprint, and a smaller tag array is faster to walk. |
| G202 | Share gadget program bodies between executors running one address space | Rejected before implementation. G201's census found about one percent of bodies duplicated between executors of one address space, so G161's sharing would save little, and sharing across address spaces would need relative link cells on the block-link path. Exact-sized bodies gained more with no hot-path change. |
| G203 | Replace the stream-address index with the body arena's own map of where live translations start | Accepted. The stream-address index was maintained on every store for a lookup made about once per hundred stores; the body arena's per-granule start bitmap answers the same question exactly, so the index and its slot fields were removed and the store path does less. Size a reverse index by how often it is read, not by how often it could be written; when the writer is the allocator, ask the allocator. |
| G204 | Replace the per-generation mappings `std::shared_mutex` with a word-sized reader-writer spin lock, and take the two process-wide locks off the miss path | Accepted. On 4 KiB pages the libc++ `shared_mutex` around the per-generation mappings capped multi-core scaling, because its shared side sleeps behind a writer and every TLB miss and fault takes it; a word-sized reader-writer spin lock with a writer-pending bit, plus lock-free lookups for the mapping-change reader and unbound run routes, multiplied several multi-core scores. G119 had rejected removing this lock when the lease in front of it was the bottleneck: a rejection is a statement about one bottleneck order, not about the lock. |
| G205 | Answer "does any native shadow alias this backing page" from a lock-free filter before the shadow index | Accepted. On 4 KiB pages every mapped page asked whether a native shadow aliased its backing through an `fstat` and a process-wide mutex, though almost none did; a lock-free hashed filter answers the common case and first-touch throughput rose substantially. The 16 KiB profile has no shadows and no such call. |
| G206 | Put the word-sized reader-writer lock on the three remaining libc++ locks a vCPU takes around every guest entry and fault | Accepted. With concurrent walkers, three remaining libc++ locks around every guest entry and fault (the native address-space registry, the execution lifecycle lock and the descriptor-to-backing table) took a large share of vCPU time; G204's lock, as `WordSharedMutex`, replaced them, and its waiter sleeps after a long spin because a lifecycle writer can wait out a vCPU still in its guest. On the older kernel the swap alone only moved the wait to the mappings lock. |
| G207 | Let the threads of one process replay their page-table changes side by side: no per-mm turnstile, exact user ranges, and no replay in front of a fault that Linux has to resolve anyway | Accepted, in both kernel lines. The sleeping per-mm turnstile cost each fault an idle-vCPU wake, and the replay in front of the Linux fault almost never published anything; the host's invalidation epoch already orders walkers, so the turnstile went, a PTE that already grants the access is replayed first, and everything else goes straight to Linux, raising first-touch and multi-core throughput severalfold on 4 KiB pages. A replay must be published in bounded batches with scheduling checkpoints, since one batch for a whole post-fork snapshot livelocked an Android boot, and the faster replay exposed a stale-page uaccess repair that was fixed in the host first. |
| G208 | Size the private gadget cache from the working set it has to hold, and let the product decide what it can afford | Accepted, with x86's X58. Re-translation counters showed the private cache thrashing on multi-core Clang through way replacement alone, and four times the slots gained substantially on Clang at a memory cost macOS can afford; macOS defaults to 262,144 slots while iOS keeps 65,536 for its jetsam budget. G166 swept this control downward and found the cliff, which was then misread as the knee. |
| G209 | Choose the victim way by second chance instead of round robin | Rejected, with x86's X59. Second-chance victim selection was free in the spare replacement bits but a wash, because a policy can learn only from cache lookups and the hottest blocks are reached through resolved links that never look up. The implementation is not retained. |
| G210 | Keep an address space's link records and indirect sites in chunks behind one open-addressed index instead of pooled node maps | Accepted. Node-based pooled maps made a link record cost several times its size; chunked records released with their address space and one open-addressed index of tagged pointers shrank link state severalfold, and multi-core Clang gained mostly because the gadgets ran faster. Link records are read on every block transition, so their allocator shapes the dispatcher's cache and TLB footprint, not only the size of the cache. |
| G211 | Keep only what a stored arm64 block cannot recompute in its body header | Accepted. A stored block's header carried the builder's whole `BuildResult`; it now keeps only what the block cannot recompute, 32 bytes, and rebuilds a borrowing `BuildResult` on demand, cutting body memory by about a quarter. A per-translation header should hold what the translation cannot recompute, not the builder's convenient type. |
| G212 | Name a stream's gadgets by 32-bit offset instead of by pointer | Measured, with x86's X76; not built. Naming gadgets by 32-bit bank offsets would shrink streams, but the decode alone, one dependent instruction in every dispatch, cost a few percent everywhere. The dispatch is the one sequence every gadget runs, so an encoding that adds an instruction there must be priced against that first. |
| G213 | Keep an arm64 link record to its BlockLink and one exit word | Accepted. A link record carried two private two-word streams in front of its BlockLink; `link_exit` now reads the PC from the BlockLink, and an FP/SIMD block keeps its `fp_link_entry` word in its own body, so a record is 40 bytes instead of 64 and FP link follows got faster. State only some targets need belongs with those targets. |
| G214 | Name a record-table entry by its record's number instead of its address | Accepted. Record chunks follow a fixed doubling sequence, so an index entry can name a record by the number it was carved under, a 26-bit number beneath a 6-bit tag, instead of by pointer. An index into storage the table lays out itself need not hold addresses; and a one-sided multi-core reading led by a noisy workload should be isolated in the final state before it is believed. |
| G215 | Report an unsigned-offset or pair transfer's fault by its position in the block | Accepted. A guest-PC word that only a fault reads was stepped over on every execution; unsigned-offset and pair transfers now carry the instruction's block position in spare descriptor bits and the boundary recovers the address from the block's runs, shrinking streams with single- and multi-core gains. X75's lesson on arm64: a word only the fault path reads is paid for on every execution, and the fault path can afford to recompute it. |
| G216 | Read a linked call's return address out of its return link | Accepted. A linked call carried the return address beside a pointer to the return link that already holds it; the call now loads it from there and carries a word less. An operand beside a pointer to a record that already holds it is a copy every translation pays for, while the replacing load is paid only by the calls that run. |
| G217 | Gather the hottest gadget entries into one page-aligned section | Rejected, with x86's X83. Gathering the entries holding almost all sampled gadget time into one page-aligned section cut L1I misses sharply but left IPC and Geekbench level; neither the option nor its generated lists are retained. Bank fetch does not bound this front end: the fetch restarts at every indirect dispatch dwarf the rare L1I misses, so a layout that makes those misses rarer has almost nothing to buy. |
| G218 | Shape a stored arm64 translation for the data cache: its stream apart from its validation words, streams on 64-byte boundaries, and a linked successor's stream prefetched 64 bytes ahead | Rejected, all three. Stream fetches are most of the engine's L1D misses, but separating streams from their validation words, 64-byte stream alignment and successor-stream prefetch each left IPC flat or worse, and an injected cold-byte test bounded the whole opportunity near a percent of Clang. The out-of-order core hides these predictable loads off one pointer, and measuring the elasticity first says so before anything is built. |
| G219 | Resolve a vCPU thread's address space without a shared reference count | Accepted. The thread-local address-space cache still handed back an owning reference, an atomic count shared by every vCPU of the process; it now lends its entry and prunes retired lifetimes only when a private retirement epoch says one has retired, which sped MMU-miss probes on the iPad. A cache that returns an owning pointer still pays the shared count it was meant to avoid. |
| G220 | Follow indirect-site misses through a per-address-space target table | Accepted. Indirect misses at many-target sites were most of the remaining executor round trips; each address space's link state now carries a direct-mapped {target, block link} table that miss exits fill and cold-section code consults after the site's cells, and for a return the ring, miss, cutting round trips about threefold with byte-identical bank text. Why this succeeded where G181's larger tier lost was not isolated; the index must mix in page-number bits, since folding with a 12-bit shift made targets 4 KiB apart collide. |
| G221 | Strip a top-byte-ignore tag in line on the vector and SIMD structure transfers | Accepted. A tagged-vector probe ran about four times faster and 3DMark Wild Life Extreme's loading and frame rate improved; the A64 corpus pins these forms under top-byte-ignore without MTE. |
| G222 | Flush a vCPU's software TLB by the sets it filled, and invalidate a range wider than the table by key | Accepted. Entering another address space cleared the whole software TLB however little had been touched; a flush now clears only the sets that fills recorded, up to a bound, and an invalidation wider than the table walks entries by key instead of pages. A process-switch probe ran about five times faster on 16 KiB pages and twice on 4 KiB, while Geekbench and 3DMark stayed level, so the flush is no measurable share of those applications. |
| G223 | Make a linked call and its return cheaper | Rejected before implementation. Call and return gadgets were over-represented in a 3DMark loading profile, but returns already stay in the stream and removing the return-record push outright made no probe faster. What remains is the dependent load of a block link or return cell that G193 priced, so a cheaper push has nothing to win. |
| G224 | Fuse the hottest adjacent gadget pairs of loader-like code | Not pursued. An execution histogram of loader-like code showed flat pair frequencies led by independent operations the core already overlaps, and the dependent chains near the top already forward. Saving one dispatch on each of the ten most frequent non-NOP pairs bounds the gain near 2 percent, as G117 found for further compare fusion. |
| G225 | Stop fewer vCPUs for a guest unmap | Measured; no change beyond G222. A guest unmap that removes published pages waits for the address space's running vCPUs, but that wait and the emulator's unmap path are a small share even of an unmap-churn probe and rare on loader-like code. The guest kernel's `uml_curr_cpu` lookup is the largest churn cost but is only call frequency, so fewer host-layer calls, not an inline lookup, would be the lever if a kernel-heavy workload ever shows it. |
| G226 | Census where the gadget caches' bytes go and why they miss before choosing a memory cut | Measured; no engine change. With macOS's 262,144 slots and four vCPUs, Geekbench multi-core left about two fifths of either engine's cache in bodies another executor of the same address space also held, and at least four fifths of its stores were code another executor had translated first, so G201's teardown figure of about one percent, on which G202 rested, does not describe multithreaded guests; copies across address spaces were negligible. Its misses were way conflicts at about 60–70% occupancy, a quarter to a third of which a 4,096-body exclusive victim tier would serve, while iOS's 65,536 slots overflowed by capacity on multi-core Clang. While WebGL Aquarium loaded and rendered, half to two thirds of stores rebuilt code of an address space the eight-space window had retired a fraction of a second earlier, and free space between live bodies in the body arena grew to three fifths of the cache; no chunk emptied, so releasing whole chunks would return none of it. | G227 | Share an address space's translations among the executors running it | Accepted with sharing off by default; `DARWIN_UML_GADGET_SHARED_BODIES=1` turns it on. On four-vCPU Geekbench multi-core sharing halved the cache, from about 316 to 138 MiB at 262,144 slots and from 183 to 91 MiB at 65,536, and raised the hit rate from 98.4 to 99.4% and from 89.2 to about 98%; single- and multi-core scores and WebGL Aquarium stayed level within noise. | G228 | Drop the guest-PC word from the remaining arm64 memory transfers | Accepted. | G229 | Keep more address spaces resident in a gadget cache: a window of twelve, sixteen or twenty-four instead of eight | Rejected. At macOS's 262,144 slots a browser guest's lookups hit more often with a larger window, its rendering phase from about four fifths to nine tenths at sixteen, but every resident address space keeps its link records until it retires, so the cache grew by two fifths at twelve, two thirds at sixteen and nearly twice at twenty-four; with half the slots to pay for twelve or sixteen it hit less often than eight, and at iOS's 65,536 slots no larger window gained. | G230 | Give a way a lookup found a second chance before its set replaces it | Rejected, with x86's X86. A per-set mark for each found way, which the round-robin hand clears as it passes, raised multi-core Geekbench's hit rate from 98.5% to 98.6% at equal memory and cut its stores by a twentieth, gained half a point at 65,536 slots, and left a browser guest's hit rate where it was. | G231 | Give each gadget cache set eight ways instead of four | Kept, with x86's X87. At 131,072 slots on the M4 MacBook Air (4 vCPUs, one Geekbench iteration, ABBABAAB), multi-core Geekbench rose 2.4% and single-core 0.5%, and WebGL Aquarium ran 2.1% faster with its load time level within noise. Eight ways at 131,072 slots against four at 262,144 held Geekbench level for a fifth less cache, a comparison the user's interim 131,072-slot default for both products superseded. | G232 | Give macOS and iOS one gadget-cache slot count | Accepted as the user's interim default of 131,072 slots on both products and both ISAs, until a later sweep over 65,536, 131,072 and 262,144 picks the final one. | G233 | Pack an arm64 gadget cache slot into three words | Accepted. A way costs its slot whether or not it holds a translation, so every byte is paid by every way of every executor: at 131,072 slots with eight ways, four executors carry 524,288 slots, 20.0 MiB of 40-byte slots. A slot is now 24 bytes: a tag, the translation, and a memo. The tag packs the key (an A64 PC below the guest address limit, or an AArch32 address under its ISA flags) under a 16-bit id the cache gives each resident address space and takes back when it retires, so a lookup is still one comparison and an empty way, whose tag is zero, matches nothing. | G234 | Halve an arm64 translation's header from 32 to 16 bytes | Accepted, with G233. Every stored translation pays for its header, and the arena rounds a body to 16 bytes, so a byte under 32 is a byte saved on every body. The header keeps what a complete block cannot recompute: where it starts, its stream and validation counts, and five flags. Where a build stopped (an address and the word it read without retiring) lives in a tail after the validation words, kept only for a block that stopped at a word the builder does not translate or that holds no instruction, the only blocks whose callers read it. Hit rates stayed level (96.60% and 96.57% private, 99.37% and 99.35% shared). Timing stayed level at that geometry. On the M1 Ultra (one Geekbench iteration), multi-core was 510.0 against 510.7 over six runs per arm and single-core at 1 vCPU 147.3 against 148.0 over three, host CPU time within 0.3%. On the M4 MacBook Air at 4 vCPUs, multi-core was 714.5 against 707.0 (-1.0%, inside a spread of 696 to 721), WebGL Aquarium averaged 25.5 against 26.6 frames per second and loaded in 44.1 against 41.7 s (three runs per arm, ABBA-ordered), so none degraded beyond the noise. A field that only incomplete blocks read costs nothing when it sits in a tail only they carry. |

## Host instructions per guest instruction

| Attempt | Disposition and lesson |
| --- | --- |
| Measure host instructions per guest instruction | Measured with per-carrier hardware counters and an exact execution histogram. Geekbench single-core costs about sixteen host instructions per guest instruction, almost all in gadget entries; memory transfers are a quarter of guest instructions but the largest share of fast-path cost, and a few hundred hot entries cover nearly every execution. It ranked the transfer and chain-exit work that followed. |
| Count why linked chains return to the executor | Measured. Most executor round trips are indirect-site misses, most of them returns, and most at sites with more targets than any small cell array can hold; each round trip costs a few hundred host instructions. This motivated the return-record ring and G220's target table. |
| Return-record ring for cached returns | Accepted, and unconditional. Linked calls push {return PC, return BlockLink} on a private sixteen-record ring, and a cached return whose cells miss pops a matching record and trains the cell, removing most return misses for a few percent on Geekbench and Aquarium; a deeper ring changed nothing. A first form that skipped cell training lost on monomorphic returns, so the ring must train the cell as the cold helper would. |
| Tagged TLB keys | Rejected, and its switch removed. Keying the software TLB by the address as presented removes the two-instruction top-byte check from every scalar transfer, but Geekbench single-core measured −1.2 percent score and +1.3 percent guest CPU time, and Aquarium −2.2 percent, none positive. As in G186 and G187, the check overlaps the TLB dependency chain rather than extending it; MTE guests would also key several tags of one page into the same set. |
| Fused transfer translation | Accepted, and unconditional. Keying same-page transfers by the page of the final byte while indexing by the first folds the cross-page check into the tag compare, since 16 KiB neighbours never share a direct-mapped set, and trims a few host instructions from every hit path for small Geekbench gains. The compare's operand form mattered: a shifted-operand `cmp` was slower than a separate shift and plain compare. With the count reduced, the remaining transfer lever is latency, not instruction count. |
| Four indirect cells and NOP elision | Four cells: removed; they cover only the minority of misses at three- and four-target sites. NOP elision: rejected, and its switch removed; leaving BTI and PAC hint entries out of the stream was level on a loader-like corpus and Geekbench, because a dispatched NOP is two predicted instructions that retire in the shadow of the gadgets around it. |

Alternating photo trials showed a small HDR gain but slower Photo Filter throughput in both candidate runs, so broader chaining did not improve multicore scaling. |
| Publish store eligibility from read-only JIT chain entries | Rejected. Focused checks passed in both page profiles after excluding reservation-establishing helpers, but alternating photo trials showed no reliable scaling gain. Broader chains also require explicit handling of a successor's deferred reservation exit; retain the existing publication boundary. |
| Shorten JIT dispatches from 64K to 4K guest instructions | Rejected. Chromium still missed its ordinary startup deadline, and paired photo subtests lost multicore throughput. |
| Enable linked x8/x9 carry or isolate the MMU execution counter further | Rejected. Linked register carry regressed paired photo subtests. Separating MMU sequence fields from its execution counter produced mixed paired results, so the original layout remains. |
## x86-64 gadget engine campaign

Measured on macOS with matched ABBA runs: focused static x86-64 probes in the
guest for the mechanism, then Geekbench 6 single-core at one iteration, which
reproduces the default run's per-workload rates, for the workload. X1 through
X13 were settled together over the full suite; later entries were each
measured against their parent on the workloads their mechanism reaches.

| ID | Attempt | Disposition and lesson |
| --- | --- | --- |
| X1 | Declare the ARMv8.5-A host baseline | Accepted as an enabler with no performance claim. The engine is macOS-only, so every host implements LSE, FlagM, FlagM2 and FRINTTS; the assembled object is byte-identical. |
| X2 | Drop result normalization the host already performed | Accepted. A W-form host instruction writes the whole 64-bit register, so width normalization was a no-op at 32 and 64 bits. 32-bit register arithmetic improved 12%. |
| X3 | Fold away the page-crossing test for single-byte accesses | Accepted. A one-byte access cannot cross a page. Byte memory operations improved 4%, and forcing the check to emit reproduced the previous engine instruction for instruction. |
| X4 | Write the deferred-flag tail as one constant | Accepted. Operation and width are macro parameters and the rest of the tail is zero, so eight bytes are one link-time constant. Compare, set-condition and locked paths improved 4%. |
| X5 | Interprocedural optimization for the translation path | Accepted on workload evidence against probe evidence. Steady-state execution is 0.5% to 2.3% slower, but four Geekbench workloads gained up to 2.75% with none regressing. Probes cannot see a change that only affects translation. |
| X6 | Resolve effective addresses without branching on the descriptor | Accepted. Every address field is a translation-time constant. An always-zero state slot lets an absent base or index be added unconditionally and lets the segment selector index a table; truncation distributes over addition, so the narrow-address mask applies once to the sum. Eight branches become none, the bank loses 13%, and memory operations improved 2% to 12%. |
| X7 | Extract byte sign masks with NEON | Accepted. Four shift-and-accumulate steps replace a loop that ran once per lane. The instruction is 78% faster; it is the core of glibc's SSE2 string routines, which a static histogram of a dynamically linked benchmark cannot see. |
| X8 | Skip the store-side publication and overlap check | First attempts rejected: hoisting the check before the store, gating it on the write-code flag, and gating it on the executable-page bit all measured no gain, because Linux grants READ_IMPLIES_EXEC to binaries without a non-executable stack marking and every data page then qualifies as executable. |
| X8b | Call code publication only when a store can publish something | Accepted. Publication was over half of every guest store's cost, and its call is a lookup that misses whenever the page holds no cached translation; recording that in the write translation, and retiring the translation when a page gains code, turns it into one bit test and made stores about twice as fast. The expensive part of a sequence can be the call it guards rather than the instructions that are visible. |
| X9 | Evaluate branch conditions from the deferred record | Rejected. The premise was that a conditional branch pays full flag materialization, but that routine exits early and is already cheap; adding a pre-check ahead of it made conditional branches 57% slower in two independent implementations. |
| X10 | Fold the recorded operation and width into flag materialization | Accepted. Both keys are constants at the recording site, but the materializer rediscovered them through two run-time chains that reached the commonest cases last. One bounded table branch now selects a body with both folded in, so the width masks, the sign-bit index and the clear mask are immediates. INC 22% faster, SETcc and ADC 18%, CMP/Jcc 15%; File Compression +3.1%, PDF Renderer +3.1%, Horizon Detection +2.9%. |
| X11 | Discard the deferred record in the bit-count family | Accepted. TZCNT, LZCNT and POPCNT define every arithmetic flag and cleared all six immediately after paying to materialize them, and every override any gadget records lies inside that same clear mask. Two stores replace the call, and a TZCNT after an ADD is 69% faster. |
| X12 | Evaluate carry conditions from the deferred record | Rejected, reproducing X9 from the opposite direction. This version replaced the call instead of adding a check in front of it, and carry-condition branches were still 70% slower. The zero-condition shortcut it imitates works because a recorded result is already width-masked and one compare answers it; carry needs the recorded operation, so the shortcut reintroduces the dispatch it exists to avoid, in a gadget rather than in a shared routine. |
| X13 | Stop advertising ERMS | Accepted at the time, superseded by X15. While REP ran as a per-element loop, withholding ERMS moved glibc's string work onto the vector gadgets and gained several percent on string-heavy workloads. A capability claim is a scheduling hint to the guest's own dispatchers, so it is a performance decision as well as a compatibility one, and withdrawing a false claim is only one of the two ways to settle it. |
| X14 | Move a repeated string operation in page-bounded runs | Accepted. REP MOVS and REP STOS paid address resolution, a TLB probe and publication once per element; a run confined to one source page and one destination page now pays them once and moves 64-byte blocks, making byte-granular REP tens of times faster. The first version fell back to the element loop whenever the destination page could hold code, and gained nothing. |
| X15 | Advertise ERMS again | Accepted, superseding X13. Once X14 made REP a block move, REP MOVSB and STOSB outran glibc's SSE2 and AVX2 routines even at short sizes, and withholding ERMS no longer bought anything measurable, so the bit went back for the guests that assume it. |
| X16 | Keep the native chain alive across a code publication | Accepted, and the largest result of the campaign. A code publication reset every link in the address space, and links came back only on translation or on one revalidating hit path, so the engine left an already resident stream every few guest instructions. Re-arming a record whenever its slot is returned, and settling a publication when a run leaves the stream as well as when it follows a link, raised instructions per stream entry about sixfold and the three lowest-scoring workloads by 77 to 134 percent; counting stream entries against retired instructions is what exposed it. |
| X17 | Materialize only the carry for the operations that need it | Accepted. INC, DEC, ADC and SBB called the full flag materializer although only CF is live; a carry-only entry through the same operation-and-width table serves the register forms, since a memory form can fault while the stale bits are still visible. Probes gained about 1.7x and workloads a few percent; the gap between the two is the operations' share of a real mix, which the probe alone could not settle. |
| X18 | Read a condition from the flags the compare already set | Accepted. After a 32- or 64-bit CMP, SUB, TEST or AND computed with the flag-setting host instruction, NZCV already holds the x86 flags, so the builder pairs such a producer with a condition consumer through one variant per condition; parity, the CF-consuming conditions after a logical operation and the narrow widths keep the deferred path, and the deferred record is still written so PUSHF and ADC stay correct. Workloads gained several percent while a probe of pure block transitions regressed: the probe measured the one thing the change does not address, and the workloads outvoted it. |
| X19 | Advertise fast short REP MOVSB | Accepted. glibc reads FSRM separately from ERMS to send short copies to REP MOVSB, and after X14 that claim holds; the workloads neither gained nor lost. As in X15, the burden falls on withholding: a neutral measurement is no reason to route the guest around a path that is not slow. |
| X20 | Widen the indirect-branch site cache from two targets to four | Rejected. Four ways per indirect site sped a probe with four call sites into one callee but left the call-heavy workloads inside their spread, because sites that miss with two ways and hit with four are rare in real code. The mechanism working is not the same as the change paying, the gap X17 crossed in the other direction. |
| X21 | Keep a call in the stream when it publishes a code write | Accepted, and the largest result since X16. A per-site exit census found one instruction responsible for most of Geekbench's exits: a linked CALL leaving because its own return-address push had published a code write. A call now publishes and continues like any store, leaving only when the write lands inside the running block, which sped call probes up to 2.4x and the call-heavy workloads by nearly a fifth. A per-site exit census finds a cause that a per-category one cannot, because the categories were chosen before the answer was known. |
| X22 | Link the block end the fetch window created | Accepted. A block cut short by the fetch window ended in an unlinked fall-through, the largest remaining exit cause; the next address is as static as a jump target, so a block that actually falls through now asks for a link, removing nearly all such exits. Clang, with much the largest code footprint, lost a little to the extra link record per truncated block and was outvoted by the other workloads. |
| X23 | Keep indirect-site training across a link cooling | Rejected. Retaining indirect-site training across a link cooling is safe, but the retained entry hits and then follows a dead link, so the exit still happens one category over; an exit census showed the total unchanged. Moving an exit between causes is not removing it, and a census of causes settles such a change without needing a quiet machine. |
| X24 | Key the indirect-branch tier on the target rather than on the branch | Accepted. A return site belongs to the call that reached it, so a function called from N places has N return targets competing at one site however many ways it has, which is why X20 failed; one direct-mapped tier keyed on the target and shared across the address space holds them all, each entry only a prediction that the follower checks against the guest RIP. Monomorphic shapes pay a few instructions for the hashed lookup, but real code outvotes the probe because a polymorphic RET was paying an exit. |
| X25 | Retire only the translations a code change covers | Accepted. A code change anywhere cooled every link in the address space; replaying the code-change ranges a reader has not seen through the cache's selective retirement, and retiring everything only when the span cannot be described, cut the link exits of browser workloads. The first attempt put a `std::shared_mutex` on the translated code-write path and cost more than the change saved, because libc++'s notifies on every unlock and ten vCPUs serialize; a sequence-stamped lock-free ring replaced it. |
| X26 | Reopen the instruction window instead of leaving at it | Rejected. Checking for interrupts and code changes in the stream at each window checkpoint, instead of leaving, removed half the remaining exits but was flat on Geekbench and slower on Chromium, and the in-stream code-change test proved load-bearing. Exits are not fungible: the cheap window exits re-enter without revalidation, while the ones that remain miss the cache or cool links. |
| X27 | Publish a code write only where some executor caches code | Accepted. Under READ_IMPLIES_EXEC every readable page may hold code, so ordinary data stores kept forcing every executor to revalidate; a per-generation registry of the pages holding cached translations lets the TLB tag a page as code exactly when a translation of it exists, with bounded waits for registration and a change-counter retry for a racing fill. Geekbench single-core rose about nine percent, matching what the profile attributed to publication. The cost of an imprecise publication is not the publishing store but every executor's reaction to it. |
| X28 | Bake registers into a generated scalar bank and read host flags at every width | Accepted. A Python generator emits a register-baked scalar bank whose register offsets and bases are immediates, which the host can forward through as G196 found, and host NZCV at every width widens the fused producers. Geekbench single-core rose 13 percent against the 35 the ceiling bench projected, and the wider fusion added nothing on top. A probe gain must be scaled by the share of real run time it touches before it is a projection. |
| X29 | Record shifts and overlay multiplies instead of materializing | Accepted. Shifts now record their own deferred operation and multiplies overlay carry and overflow instead of materializing flags eagerly, for a few percent. The campaign then stood at 1.42 times FEX on the same kernel, short of the summed projections because each assumed halving work that turned out to be a fraction of the total; FEX still led where vector and memory-transfer cost, not flags, set the pace. |
| X30 | Carry host flags across a flag-neutral transfer | Accepted. A flag-neutral register MOV, MOVZX, MOVSX or LEA between a compare and its consumer now passes the producer's host flags through instead of sending the consumer down the deferred path, roughly halving such loops. A memory destination still ends the fusion, because a store's epilogue compares addresses. |
| X31 | Retire only the TLB entries a mapping change covers | Accepted. Every engine entry cleared the whole software TLB, so a fault-heavy guest re-walked its page tables after every fault; replaying the mapping ranges a reader has not seen, the service X25 introduced, retires only the covered entries and falls back to a clear for large or undescribable spans, for broad gains. |
| X32 | Take the preserved carry from host flags in INC and DEC | Accepted. INC and DEC called the carry materializer to settle the pending producer; when the builder knows the producer, a variant per carry source reads the carry in one condition, nearly halving an INC/DEC loop. The suite barely moved: the mechanism is a large share of very little. |
| X33 | Translate a conditional branch's fall-through inline | Accepted, and the largest single change of the campaign. Continuing the decode past a conditional branch puts its fall-through in the same stream, the arm64 engine's G162, which also speeds the taken shape because blocks grow, and it raised every Geekbench workload and the single-core score by nearly a fifth. |
| X34 | Bias the retirement counter by the dispatch budget | Accepted. Counting retirement from minus the dispatch budget makes each linked edge's budget test the sign of one addition, the arm64 engine's G180 inverted; a small probe gain with less gadget text and a neutral suite is worth keeping. |
| X35 | Run the SHA-256 message schedules on the host SHA unit | Accepted. SHA256MSG1 and SHA256MSG2 map onto the host's SHA256SU0 and SHA256SU1, the latter with its third addend suppressed, making a message-schedule loop several times faster with bit-identical results; Geekbench has no SHA workload. The rounds stay scalar because x86 performs two where the host pair performs four, and SHA-1 stays scalar because x86 numbers its words from the high lane down. |
| X36 | Publish the guest rounding mode for the whole dispatch | Accepted. The dispatch publishes the guest's MXCSR rounding mode into FPCR at entry and on every MXCSR write, so conversions use the mode-relative `frinti` instead of a branch tree, the arm64 engine's G30. The first attempt restored a saved FPCR at leave, but a gadget that faults out of a stack-using sequence reaches leave with a different stack pointer and restored garbage that enabled host FP traps; deriving the restore from FPCR itself needs no saved copy. |
| X37 | Bake the vector register and base into 128-bit transfers | Rejected. A bank baking the vector register and base into 128-bit transfers sped the [base + displacement] shape but not the indexed shape SIMD loops actually emit, while adding hundreds of KiB of text that every workload pays for. X28's lesson in its other direction: a bank entry is worth its text only if it bakes the shape the workload uses, and for vector memory the index is part of the shape. |
| X38 | Fold the page-crossing test into the TLB tag compare | Rejected on correctness before it was measured. An unsigned range check against the tagged page base cannot replace the tag compare and crossing test, because a reset entry then falsely hits a window of addresses above its tag, the null page for the reset tag; comparing the last byte's page instead lets a crossing access hit when the set hash maps both pages together. A tag compare carries an invariant a range check does not, that this entry describes this page, and the invalid entry is where the difference shows. |
| X39 | Leave a NOP untranslated | Rejected. Eliding NOPs sped padded loops but broke the one-retirement-per-architectural-instruction contract that budgeted replay and the K-trace corpus pin, and restoring the count costs about what the dispatch saved. The retired count is the unit of guest progress, not bookkeeping, and an instruction that does nothing is still one. |
| X40 | Discard the pending record in operations that define every flag | Accepted. Instructions that define every flag they do not leave undefined (COMISS and UCOMISS, PTEST, the packed string compares, bit scans and counts, the BMI flag writers) now clear the pending record with two stores instead of materializing it first, while BT and its siblings write their carry into the override; probes gained up to twofold and the workload mean slightly. |
| X41 | Write scalar vector moves with one full-width store | Rejected. Replacing a scalar vector move's zeroing wide store plus narrow store with one full-width store was inside the noise, and the merging register form was slower. This core does not stall on a wide load after a narrow store into the same slot at this distance; the store-forwarding folklore is from other microarchitectures. |
| X42 | Keep AESKEYGENASSIST in the vector unit | Accepted. AESKEYGENASSIST now stays in the vector unit, with RotWord as a shift and shift-insert, a broadcast round constant and zips, instead of crossing to the general registers; a key-expansion probe gained while Ray Tracer, the only workload expanding keys, stayed flat. Kept for the probe and the shorter, transfer-free body; the instruction's profiled share did not survive the suite. |
| X43 | Round PMULHRSW with SQRDMULH | Accepted. PMULHRSW now uses SQRDMULH, with the one lane where both inputs are 0x8000 (x86 wraps, the host saturates) flipped back by a mask built before the multiply so an aliasing output is compared first; probes gained but the suite was flat. With X42 this is the second profiled share that did not survive the suite, so per-gadget attribution is suspect for memory forms and their shared tails. |
| X44 | Give the software TLB four times the reach | Accepted. The direct-mapped software TLB grew fourfold, to 32768 entries in 1 MiB, because image workloads walk more pages than the old table reached; small footprints drift slightly on host TLB reach and the suite gained modestly. The probes understated the suite because a benchmark loop touches its pages in order while a real workload interleaves them with other data. |
| X45 | Park the carry INC and DEC preserve instead of settling it | Accepted. When the builder cannot see the carry's producer, INC and DEC now park the pending record in a carry slot with a pending bit instead of settling it, and only a reader of the carry through such a record computes it; a unit test drives every reader across widths and producers. Most workloads gained: a flag no one reads costs nothing to leave unread, and the carry INC and DEC preserve is almost never read through them. |
| X46 | Carry host flags across a baked memory transfer | Accepted. The baked bank's loads, stores, PUSH and POP now leave NZCV intact (the tag test is an exclusive-or and a compare against zero, the store epilogue orders addresses by the sign of a difference, and miss tails save NZCV), so a fused condition reaches its consumer across them. The ordinary bank still ends a fusion, because only the baked entries were audited for flag neutrality. |
| X47 | Fix the generated NaN without a branch | Rejected. Replacing the indefinite-NaN fix's rarely taken branch with a branch-free mask made every floating-point result slower. A branch whose body is skipped is not a cost to remove; it is what makes the body free. |
| X48 | Re-check the stack's own TLB entry | Accepted. The execution context keeps the TLB entry the last stack access used, and a matching tag with no code bit and no pending publication returns the host address directly, sparing PUSH, POP, CALL and RET the hash and table read; stores still join their overlap epilogue, and a page holding cached code always carries the code bit. Small, broad gains. |
| X49 | Take a vector operand from the register the gadget before it left it in | Accepted. A vector integer register form's result stays in host `v4`, and `v5` at 256 bits, and the builder sets a descriptor bit when the gadget immediately before wrote exactly this register and width, so a dependent chain takes the operand from the register; only register forms qualify, and a block starts with nothing available, so a replay cannot inherit a stale register. Dependent chains ran more than twice as fast. An unsound always-forward build measured the ceiling first, which is what made the mechanism worth the builder state. |
| X50 | Forward vector results in the map2 and floating-point families too | Rejected. The same forwarding in the map2 and floating-point families doubled their probe but lowered the suite, because the test sits in front of every gadget and those families chain too rarely to pay. A mechanism worth its test in one family is not worth it in the next, and only the suite separates them. |
| X51 | Read the x86-64 program cache counters on Clang | No change. Program-cache counters on Clang showed validation free, always settled by the code-page stamp, and about a quarter of lookups ending in a fresh translation, which was read as cold compiler code; X58 corrected that reading, because this census never counted evictions. The counters stay unprinted in the product. |
| X52 | Feed a vector memory operand from the baked address entry | Rejected. Giving every vector memory form a second entry that joins past the address decode, fed by the scalar bank's shared address entry, changed nothing: the extra dispatch costs what the decode did. X37 baked the operand into the gadget and this shared the address instead; the dispatch eats the saving either way. |
| X53 | Release unused x86 translation capacity | Accepted. Short blocks retained the decoder's 64-instruction allocation in every vCPU cache. Compact decoded and native streams before publication so retained storage follows the actual block length. Both ISAs now use common private-cache geometry controls. This establishes a storage reduction, not a throughput gain. |
| X54 | Order guest memory accesses across vCPUs | Accepted as a correctness requirement. Without total store order and the full fence of a LOCK-prefixed instruction, multi-threaded guests on several vCPUs crashed or deadlocked, because the host really reorders; a `dmb ish` on the way out of every gadget that touches guest memory fixes it for under two percent of the single-core suite, and neither `ldar`/`ldapr`, `stlr` nor the LSE atomics are cheaper on this host. Scores from single-vCPU guests before this entry did not pay it. |
| X55 | Make the code-page registry's membership exact | Accepted as a correctness-of-performance fix. The code-page registry counted per hashed bit with a hash that keeps neighbours adjacent, so a run of code pages could mark a thread's stack as code; every push then published and every vCPU retranslated every block, losing nine tenths of its speed in one run in ten. An exact count per page behind the bit, striped over the word-sized lock, removed it. A conservative filter is harmless only if a false positive is cheap, and here one on a hot page was paid by every vCPU on every block. |
| X56 | Keep a cached translation across another vCPU's code change | Accepted as a correctness-of-performance fix, and the other half of X55. Validation discarded a cached program whenever the address space's code-change sequence had moved, which under legitimate fast publication meant every block on every other vCPU; taking each page stamp once, before the bytes it certifies, makes it a lower bound, so only a publication that touched the program's page invalidates it, while a moved mapping sequence or raised interrupt still abandon validation. A freshness token must be taken before the data it certifies; taken afterwards it needs a second, global guard that every other vCPU pays for. |
| X57 | Publish a code change for every executable page a program stores into | Accepted as a correctness fix, and the loose end X56 named. Publication was keyed on the program, so a store into a second executable page after the first published nothing, and other vCPUs kept a stale translation of that page; the program now carries the page it last published, a store to a different page owes a record, and the decision stays the same length in the bank. A suppression keyed on the actor is sound only when the thing it protects is also the actor's; this one protected a page, so the page had to be the key. |
| X58 | Size the private program cache from the working set rather than from one number for every product | Accepted, with arm64's G208. Eviction-attributed re-translation counters showed every executor of multi-core Clang at full occupancy against a working set about three times its slots, nearly every translation a repeat lost to replacement, which corrects X51; four times the slots gained substantially on Clang. macOS takes 262,144 slots although an x86 slot then cost several times an arm64 one, which X77 and X80 later reduced. A cache at full occupancy against a working set several times its size is one to enlarge, not tune, and the counter that says so separates a first translation from a repeat. |
| X59 | Choose the victim way by second chance instead of round robin | Rejected, after measuring the ceiling first. Shadow caches driven by the real reference stream showed that a policy which learns only from lookups, since a resolved link never enters the cache code, could save little, and that LRU on lookups alone did worse than second chance because it ages out the hot, well-linked blocks it cannot see; the built policy was a wash. A replacement policy is worth only what it can observe; simulate the achievable ceiling from the real reference stream before building the policy. |
| X60 | Build a translation in buffers the thread keeps, and allocate the finished block | Accepted, in a shape the suite corrected. Decoded instructions and native words now accumulate in two per-thread buffers and the finished block is copied out at its exact size, cutting translation cost; copying stream and decoded instructions into one allocation moved hot streams among cold data and cost the browser workload, so they became one hot and one cold allocation. Allocation count and locality are separate questions, and merging allocations is free only when what is merged is touched together. |
| X61 | Fetch an instruction's bytes in one page-bounded window | Accepted. The decoder fetched guest bytes one virtual call at a time; it now fetches up to fifteen bytes in one page-bounded window, which cannot fault for a page the instruction has not reached and faults exactly where the decoder wanted when it does. A test pins both halves of the page bound, and widening the window to two pages fails the second-page write race. The cost of a byte-granular reader is the call, not the byte. |
| X62 | Put a translation's saved source bytes in the translation | Accepted. A translation's saved source bytes now live at the end of the allocation holding its decoded instructions instead of in a vector built afterwards, removing an allocation per translation and a header per slot. A thing produced with an object and only meaningful beside it should be allocated with it. |
| X63 | Answer a repeated code-page handle without a lock | Accepted. The code-page record lookup, made before every block read and revalidation, sat behind libc++'s `std::shared_mutex`, which serializes readers; records are created once and never moved, so a lazily filled two-level index of atomic pointers answers every repeat and only a first sighting takes a plain mutex, cutting multi-core translation cost. A reader-writer lock is the wrong tool for a table that only ever grows; it needs a way to publish, not a way to share a lock. |
| X64 | Fetch a whole block through one window | Accepted, and smaller than it looks. The builder shares one 128-byte window across a block's decodes and refills it only when a decode needs bytes outside it, which cut fetches per block to about one but translation cost only slightly: nearly all of the sampled fetch cost was the first call. Once the calls are down to one per page-resident line, the rest are nearly free, and a sample's attribution to a symbol does not say which of its calls are expensive. |
| X65 | Take a packed-integer operand from either side of the gadget before it | Rejected. Forwarding the right operand of a packed-integer register form too, where X49 forwards the left, left the suite unmoved although the profile had put much of Object Detection's time on that load. An engine test stays behind, pinning which bit forwards which operand, that any instruction between producer and consumer withdraws both, and that a block entered at the consumer forwards nothing. |
| X66 | Forward from every producer, and into the floating-point family | Rejected, and X50 with it. Widening forwarding to every producer that retires into `v4`/`v5`, and into the floating-point family, grew the text and moved no workload. A sampled operand load is where the machine waits, not what it waits for: these gadgets are bound by the work around the load, and X49's families are as far as the mechanism pays. |
| X67 | Write a 256-bit vector result as one store pair | Rejected. Writing a 256-bit result as one `stp` was slower across the suite, even on workloads that write almost no such results, because the next gadget's 16-byte operand load cannot forward from a 32-byte store. Loads are X68. |
| X68 | Load a 256-bit vector operand as one pair | Rejected. Loading 256-bit operands with `ldp` left the suite flat, and with X65 to X67 it settles the profile's question: these gadgets are not short of operand bandwidth or latency, so further work on the vector gap belongs in how many gadgets a 256-bit instruction costs. Clang moving on a vector-only change was the bank moving under a smaller text, not the change. |
| X69 | Keep a translation's bytes, and its decoded instructions only where a replay asked | Accepted. A translation carried about 1.8 KiB of decoded instructions whose only reader is the budget-limited replay; a build now keeps its stream and source bytes, a replay decodes the block back from those bytes, and only a block replayed before keeps its decoded form, cutting resident translation memory about fourfold with workloads flat. Dropping the copy outright lost 2 percent, because the replay is warm and concentrated. "The only other reader is a rare path" is a measurement, not a reading of the code, and when the path is warm the storage is owed only to the blocks that have proved they need it. |
| X70 | Stop a plain long-mode address once its components are summed | Accepted. In long mode with no segment override and no narrow address size, masking and adding a segment base are identities, so the builder proves that and sets one descriptor bit on which the gadget stops at the summed address; the general tail moved to `__gadget_cold`, since keeping it inline cost hot text and Clang, and forcing the bit on fails the addressing test on an FS base. Image workloads gained several percent. A descriptor bit the builder can prove beats a gadget variant per shape, but only when the shape it does not serve leaves the hot instruction stream as well as the fast path. |
| X71 | Leave a read-only memory gadget through an acquire barrier | Rejected. Total store order lets a load overtake an older store, so a gadget that only read guest memory could leave through `dmb ishld`; widening X54's mark to read or write turned about half the barriers into acquire barriers at identical text size, and it bought nothing measurable. At the time, unit builds linked a strict-TSO bank, so the ordering test could not see the marks; that build was removed with the ARM64EC products (c937108d). An ordering relaxation has to be measured against a barrier that is actually costing something. |
| X72 | Settle a store's publication in five instructions | Accepted. The opening profile ranked candidates by what executes rather than by a static
instruction histogram, and so retired several planned items that barely ran:
truncating FP conversion and scalar FP compare, locked read-modify-write,
gadget-TLB associativity, and specialized shifts and stack fusion. Its largest
item, leaving and re-entering the stream, was not answered by any of the
structures the plan proposed; counting exits by cause found the existing chain
machinery switched off wholesale (X16), and later exit censuses drove X21 to
X26. What remains of stream re-entry is exits that miss the program cache or
re-arm a cooled link, so further work belongs in translation and validation
rather than in the count of returns.

Five lessons generalize. Whether a page might hold code is not a condition this
engine can branch on to save work. An executable-stack declaration has Linux
mark every data page executable, and a probe whose data segment is plain
read-write with a non-executable stack still reported code-capable on every run,
while across the workloads publication actually fires on well under one percent
of self time. The predicate is true far more often than publication is needed
and cannot be predicted from the guest's own markings, so X8's first attempts
and X14's first version both measured nothing by skipping work when it was set.
The work has to become cheaper rather than conditional. Instruction count
inside a gadget is a weak predictor: the changes that paid removed a loop, a
call, or a branch, and those that only shortened a straight-line body did not.
A probe measures the mechanism it names and nothing else, so a candidate that
only affects translation, or that trades throughput for latency, needs a
workload to judge it. And laziness is worth paying for only where retrieving
the deferred value is cheaper than computing it: X9 and X12 failed at the same
boundary from opposite directions, while X10 succeeded by making the deferred
path itself cheaper rather than trying to avoid it. Finally, a profile ranks
what runs but not how often a structure is bypassed; where a fast path exists,
count how often it is taken before assuming its cost is the thing to reduce.

## x86 equality conditions in Wine

| Attempt | Disposition and lesson |

| Avoid full flag evaluation for equality-only consumers | Accepted. | Attempt | Disposition and lesson |

A JIT memory word that falls back to its semantic helper switches the FP
environment to the host's and back, about 14 ns on the M1, and ends its block;
the whole exit cost about 30 ns. GB5 Ray Tracing spent 37 percent of its vCPU
samples in those switches at 4 KiB. Exit counts are per run of a counting
build on the M1.

| Attempt | Disposition and lesson |
| --- | --- |
| Prove a memory run's page from the bytes it accesses | Accepted. A run of unsigned-offset accesses through one base proved and translated the base itself, so a base near a page end whose fields all lay further on failed on every execution and ran its first access in the helper. The run now translates its first accessed byte. Ray Tracing's exits fell from 59 to 3 million at 4 KiB and from 15 to 0.8 million at 16 KiB, and its M4 score at 4 vCPUs rose from 129 to 522 at 4 KiB and from 309 to 642 at 16 KiB. ## AArch32 JIT: memory access

Inline TLB probes are 20% to 40% of the host instructions executed in the
memory-heavy single-core workloads, so a shorter probe is a general saving.

| Attempt | Disposition and lesson |
| --- | --- |
| Probe the 4 KiB TLB in two fewer instructions, skip the crossing test of an access aligned to its size, and fold the crossing test into the tag compare | Accepted as three changes with one measurement: single-core +5.6% over the block before them, 11 of the 12 workloads level or faster (Gaussian Blur 1.11, Machine Learning 1.14, SQLite 1.09, Rigid Body 1.07). The A32 probe is its own copy of the shared sequence: bit i of the index is bit 12+i of the address xor bit 25+i, which is one xor with the address shifted by 13 and one extract, and the tag compare shifts the address itself. Comparing the tag with the page of the last byte makes the crossing test free, because the entry belongs to another page when the access crosses. The tests compare the emitted words, because a probe with a wrong index passes every behavioral test by missing. |
| Add the TLB delta in the access, as `[x9, w8, uxtw]`, instead of before it | Accepted. The add was 2.8% to 5.1% of the executed host instructions and three quarters of the accesses after it have the register-offset form. Single-core +4.8% over the step before it together with the revert of the skip region below (Speech Recognition 1.16, Camera 1.12, Text Compression 1.05). A pair, a multiple transfer, an acquire or release, a lane transfer and a store that records its host range keep the add. |

## AArch32 JIT: blocks, links and registers

| Attempt | Disposition and lesson |
| --- | --- |
| Go on past a conditional forward branch (B, CBZ, CBNZ) in a block, with a cold side exit for the taken path | Accepted. Every conditional branch had ended a block with two links, so the short blocks of the benchmarks paid a link sequence and the loads of the next block on every transition. Single-core +9% (Text Compression 1.06, SQLite 1.09, N-Body 1.03, Face Detection 1.02). |
| Run a block that branches back to itself as a host loop | Accepted. A probe compilation records the registers the body holds, the loop loads them once and the back edge publishes only the flags and checks the budget. Single-core +2.2% with Machine Learning +13%, measured on a loaded host. |
| Hold the loop's most used registers, not its first | Superseded. Neutral alone (1.004) and made moot when a translation took all fifteen core registers. |
| Keep the target of a forward branch in the block, over the instructions it skips | Rejected and reverted. Four concurrent repetitions of the twelve workloads gave 0.996 of the block before it. It carried the most state in the compiler (a second set of bindings and flag states for the skipping arm, a join that reconciles them, a retry that compiles the block again without a region that does not fit, a budget credit for the skipped instructions) and the cold side exit it avoids costs one link. It also made reachable a latent defect, which the revert makes unreachable again: a cold path stores the dirty registers through the bindings at the end of the block, which is wrong once a binding is forgotten in the middle of one, and the join was the only place that forgot them. |
| State the loaded FP state and the native environment in every chain's link selector | Accepted. A chain's selector described its first block, so a loop of an integer block that stores and a block of Neon arithmetic returned to the executor at both edges of every iteration: two blocks made 160 of Structure from Motion's 240 million returns. Returns fell from 247 to 64 million. |
| Look up an indirect branch's target in a per-executor table behind its two cells | Accepted. A return from a function with more than two callers cannot keep its targets in two cells (libm's `lroundf` from four places made 36 million returns in Structure from Motion). A 4096-entry direct-mapped table of trained targets takes the third level, tagged with the link epoch because it outlives address spaces: the first version without the tag followed another address space's function at the same address and killed init, which the userspace smoke found. Returns fell from 64 to 19 million in Structure from Motion, from 13 to 2.0 million in Image Inpainting, from 16.8 to 5.2 in Speech Recognition. Together with the selector row, single-core +10% (SQLite 1.35, Structure from Motion 1.10, Horizon Detection 1.04) over the two repetitions taken on a quiet host. |
| Hold all fifteen core registers in the host (x22 to x28 beside the eight) | Accepted, small on its own: single-core +0.7% (Structure from Motion +2.4%). A block that names r0 to r12 did 25 register-file accesses per pass with eight host registers. It is the precondition of the next row. |
| Keep the core registers in the host across links | Accepted. A linked translation loads the fifteen registers once, before the internal entry that only the executor reaches, a link leaves them in their hosts and only a return to the executor writes them back, in pairs. Single-core +4.1% over the step before it (SQLite 1.13, Speech Recognition 1.12, Image Inpainting 1.12). Registers the link sequence had used as scratch (x12 and x13) became resident, and two conversion lowerings that used the hosts of r0 to r2 as scratch became a defect that the change exposed: a kept register set turns every hard-coded scratch register into one, so the tests write r0 to r2 before the instructions that use scratch. |
| Go on past a conditional branch back | Accepted. A loop body that tests its bounds with several branches back to the loop's increment was a chain of two-to-four-instruction blocks that fall through nearly always, each paying a link. Horizon Detection +3.2%, Speech Recognition +3.9%. A branch back to the block's own first instruction still ends it, for the host loop. |

## AArch32 JIT: candidates not built

| Attempt | Disposition and lesson |
| --- | --- |
| Cache the last page ahead of the TLB probe | Rejected before building. The crossing test an access needs beside the cached page compare costs what the cache saves. |
| Skip clearing the exclusive monitor on ordinary stores | Rejected. An ordinary store may clear the local monitor, and a reservation left standing lets a later store-exclusive succeed where the architecture says it fails. |
| Keep the vector registers in the host across links as the core registers are | Not built. Vector spills and fills are 2% to 6% of the executed host instructions in the floating-point workloads, an expected 1% of the single-core score, for a fixed binding of the A64 compiler's dynamic vector residency and every helper that reads the vectors. |
| Fold the alignment test into the tag compare, and drop the repeated monitor clear after a store in the same block | Not built. The alignment test is 0.2% to 1.9% of the executed host instructions (5.2% in N-Body) and the clears 0.5% to 1.3%; neither is a gain a paired run resolves. |

## AArch32: AES-XTS and Face Detection

With the JIT at 0.89 of aarch64 single-core on the M1, AES-XTS (0.26) and
Face Detection (0.34) were the lowest Geekbench 5 armv7 workloads. Each JIT
row compares concurrent pairs of 1-vCPU guests on the M1 Ultra at 4 KiB, one
iteration, the order swapped every repetition, against the commit before it.
Over the three accepted rows the armv7 single-core score rose 1.08 (Face
Detection 2.50, Camera 1.37, Horizon Detection 1.32, Structure from Motion
1.23, Image Inpainting 1.21, Rigid Body Physics 1.17, HDR 1.11, every other
workload within 2%), an estimated 0.85 of aarch64 for Face Detection and
0.97 for the single-core score. The aarch64 emission is unchanged.

| Attempt | Disposition and lesson |
| --- | --- |
| AES-XTS in either engine | Intrinsic; nothing changed. The armv7 binary holds no AESE, AESD, AESMC, AESIMC or VMULL.P64 in either instruction set, although the guest advertises the AArch32 crypto extension and OpenSSL in the armhf guest uses it. Geekbench encrypts with lookup tables, 11 to 19 times the guest instructions that the aarch64 build's AES instructions need for the same work, and both engines retire those instructions at least as fast as aarch64 ones. The ratio is 0.26 in the JIT and 0.07 in the gadget engine, which runs aarch64 AES as fast as the JIT does. Count the instructions per unit of work of the two binaries before looking for an engine cause. |
| Face Detection in the gadget engine | Nothing specific to armv7: 0.77 of aarch64. The gadget engine addresses each S register in CpuState, so the lane inserts of the JIT rows below do not arise there. |
| Convert singles to and from integers in the vector unit (JIT) | Accepted. VCVT between a single and a 32-bit integer went through W0 twice; the A64 scalar SIMD forms round, saturate and raise the flags as the general-register forms do. Face Detection 1.41, Camera 1.22, Structure from Motion 1.16, Horizon Detection 1.11, Speech Recognition level. The AArch32 corpus could not tell FCVTZS from FCVTNS, because no conversion input had a fraction; its simd-convert suite now has them. |
| Keep S registers in V registers through runs of VFP instructions (JIT) | Accepted. An S register is a lane of its resident Q register, so every single-precision instruction moved its operands out of their lanes and inserted its result, and an insert rewrites the whole Q: Face Detection's four independent chains on S8, S10, S12 and S14 (lanes of Q2 and Q3) waited for each other's inserts. In a run of unconditional single-precision instructions an S register now keeps a copy in a low V register that later reads take; the insert still writes the Q, and an instruction that may write an S register another way or use those registers forgets the copies. Face Detection 1.70, Horizon Detection 1.19, Camera 1.12, Structure from Motion 1.09, Speech Recognition 1.03. Lanes packed into one register serialize independent work through their inserts; a copy outside the packing removes the dependency without changing what exits and links see. |
| Let an A32 block hold all 64 instructions (JIT) | Accepted. The 60-instruction target leaves room for an IT block that a block's last instruction opens, which only T32 has. Face Detection's feature loop ran a block of 60 and a block of the four instructions after it on every pass; one block of 64 saves a link: Face Detection 1.04 (nine of ten pairs), the other workloads within 1%. |
| Link a loop block's exit through the unconditional B after it (JIT) | Not built. Face Detection's inner loop leaves into a one-instruction block, a B to the outer loop's head, on every pass; the row above puts one link at about 4% of that workload, but the change reaches into the host loop's exits, budget and saved guest words. |
| Cache the TLB page for a run of table loads | Not built. After the rows above, TLB probes are 38% of the host instructions in Face Detection's loop and 57% in AES-XTS's table rounds, but a translation holds all fifteen core registers, which leaves no host register for a cached page, and the last-page cache above was rejected for the crossing test it needs. |

## AArch32 gadgets against the Raspberry Pi 4

Each row runs Geekbench 5 armv7 single-core in the gadget engine at 4 KiB on
the M1 Ultra: concurrent pairs of 1-vCPU guests, one iteration, the order
swapped every repetition, against the commit before it. The engine's gap is
its armv7/aarch64 ratio divided by the same ratio on a native Raspberry Pi 4
(Cortex-A72). At the start it was 0.85 for the single-core score, with
Gaussian Blur at 0.57, Machine Learning 0.59, and Navigation, Ray Tracing,
Image Compression and Speech Recognition near 0.78.

| Attempt | Disposition and lesson |
| --- | --- |
| AES-XTS against the Pi 4 | Measured; nothing to change. The Pi 4's Cortex-A72 has no AES instructions, so both of its builds encrypt with tables and armv7 reaches 0.84 of aarch64 there. Our 0.07 measures the host AES instructions our aarch64 guest runs, not a slow armv7 path. The armv7 rounds are 47 percent table loads through the TLB probe, which the next row shortens for every load. |
| Key the 4 KiB AArch32 TLB probe by the access's last byte | Accepted. The folded 4 KiB index puts pages n and n + 1 in one set only when n has 25 trailing ones, which no 32-bit page number has. The crossing test therefore joins the tag compare as it does on 16 KiB, and the set index takes one xor and one extract: 9 probe instructions instead of 12 for each multi-byte access. Single-core +3.1 percent (five of six pairs higher, none lower) and 18 of 21 workloads higher: Structure from Motion +5.9, Camera +5.3, Navigation +4.4, Gaussian Blur +4.2. Machine Learning and AES-XTS were level. N-Body's 0.97 did not reproduce: the change with every later gadget padded back to its old address beat the commit before by 1.5 percent and tied the change. A wrong set index only shows as misses that the C++ fill path hides, so the control test fills an entry through that path and must hit it through the emitted probe. |
| Run conditional data processing that sets no flags as a select | Accepted. A conditional instruction went behind a skip gadget whose branch follows the guest's condition, which the image kernels compute from their data, so the host mispredicted it: skips took 4.5 to 6.9 percent of the timed samples of Image Compression, Ray Tracing, Speech Recognition, Navigation and Face Detection. MOV, MVN, ADD, SUB, RSB, AND, ORR, EOR and BIC of an immediate or a register, and MOVW, now look the condition up in a truth table over NZCV and select the result or the old value. Face Detection +6.4 percent (all pairs), Image Compression +2.7 to +3.6, PDF Rendering +2.3, Text Compression +2.1; the single-core score was level (geometric mean +0.7). Camera and Structure from Motion were 2 percent lower in three of four pairs. A branch on guest data costs more than the work it skips. |
