# Mainline Linux 6.18 source policy

This directory owns the maintained stable Linux 6.18 source identity, local
Darwin UML patch series, complete kernel configuration, standalone build
policy, and accepted artifact descriptors.

Exact upstream commit/tree, the ordered series, and the final tree they
produce live in [`patches/metadata.env`](patches/metadata.env); the bridge ABI
identity is [`../common/abi/identity.env`](../common/abi/identity.env). The
normal arm64 slices apply the shared
[`kernel/common/patches`](../common/patches) series, which the Android line
also applies, and then this line's overlay in `patches/series`. The dedicated
x86_64 userspace slice applies after them and owns only its config and patch
overlay under [`slices/x86_64`](slices/x86_64). Its metadata names no upstream
identity: the slice takes this line's, and the series tooling rejects a copy.
Those machine-readable files are the source of truth; the final tree is the
identity an artifact is accepted by, and replay commit IDs and binary hashes
are observations.

The shared stateful Virtio video decoder is built in for every product in this
line. Its [wire contract](../common/video/README.md) is synchronized from the
canonical header and its implementation is a topic in the shared series.
The host exposes hardware decoding through V4L2 independently of the GPU.

The shared series also carries topics Android relies on: an initrd read from a
byte range of a host file (`initrd_offset=` and `initrd_size=`), arm64 kernel
API header generation, arm64 Rust target flags, the arm64 system-mapping
sealing capability, and the Kernarium Virtio battery driver. This line's
configuration leaves Rust, `MSEAL_SYSTEM_MAPPINGS` (which `CHECKPOINT_RESTORE`
excludes), and the battery driver disabled.

## Source preparation and replay

Linux must be checked out on a case-sensitive filesystem. Copy
`source-location.conf.example` to the ignored `source-location.conf` and set
its single absolute `UML_KERNEL_SOURCE_DIR` value.

```sh
kernel/mainline-6.18/scripts/prepare-source.sh
kernel/mainline-6.18/scripts/prepare-source.sh --verify
kernel/mainline-6.18/scripts/prepare-source.sh --slice x86_64
kernel/mainline-6.18/scripts/verify-replay.sh \
  --work-root /case-sensitive/path
```

Preparation uses the pinned Git cache and creates the managed replay branch.
`--no-fetch` requires the exact commit to exist locally. `--recreate` may
replace only a clean stale managed replay; it never replaces an arbitrary
checkout.

Replay, rebase, and next-base commits keep each topic's author and are
committed by whoever Git resolves for the caller; that committer never reaches
a patch file. A patch's only identity is its topic's author, so
`scripts/patch_series.py export` refuses a placeholder author or one Git
invented from the host name, such as a `localhost`, `.local`, `.invalid`, or
`example.com` address. The topic's owner fixes it with an ordinary amend such
as `git commit --amend --reset-author`. Tools never name or rewrite an
identity.

`verify-replay.sh` starts from the pinned upstream commit, verifies the shared
series, branches and verifies the x86_64 overlay, and by default builds arm64
16 KiB, arm64 4 KiB, and x86_64-userspace 4 KiB kernels. Use `--skip-build`
only when source replay is the intended scope. Kernel builds use all online
processors unless `UML_KERNEL_JOBS` or `--jobs` supplies a limit.

## Patch maintenance

The shared series and this line's overlay are generated by
[`kernel_series.py`](../common/tooling/kernel_series.py) from the managed
replay: shared topics end at `codex/linux-6.18-common`, and mainline-only
topics follow up to `codex/linux-6.18-darwin`. Amend, reorder, add, or drop
commits there, then run:

```sh
kernel/mainline-6.18/scripts/rebase-patches.sh
kernel/mainline-6.18/scripts/rebase-patches.sh --slice x86_64
```

Each run exports its slice's series, named by topic subject, and records the
final tree. The arm64 run exports the shared series too; a shared change then
needs the Android refresh in [its README](../android-6.18/README.md) in the
same change. The x86_64 run first rebases its overlay onto the current arm64
branch. A patch file changes only when its own topic does. Never edit patch
files, `series.tsv`, or the final tree by hand.

`check-next-version.sh --work-root PATH --ref REF` (see `--help`) rebases a
replay onto a development ref and reports the topics that need a port, then the
`git range-diff` of the rest.
The series is maintained locally; no tooling submits or pushes it.

## Kernel configuration

`config/common.fragment` is the complete shipped policy. The build copies it
as the starting `.config`, applies exactly one page fragment, runs
`olddefconfig`, and verifies that every requested symbol resolved as declared.
`build/build-kernel.sh --lockdep` also applies `config/lockdep.fragment`
last, for a lock-checking probe with lockdep, its hardirq-state tracking,
`DEBUG_ATOMIC_SLEEP`, and `DEBUG_VM`. Publish such a kernel only to a scratch output root and select it
through `UML_MAINLINE_618_KERNEL_ARTIFACT_DIR`; it is never an accepted
artifact.

The normal arm64-userspace profiles are:

- 16 KiB pages from `kernel/common/config/page-16k.fragment` (default); and
- 4 KiB pages from `config/page-4k.fragment` (compatibility).

The separate x86_64-userspace slice is 4 KiB only. It composes
`slices/x86_64/config/userspace.fragment` after the shared common and 4 KiB
fragments and applies only the patches in `slices/x86_64/patches`. The kernel
still executes its UML kernel mode as native arm64, but its userspace ABI is
fixed to the x86 family: it accepts x86_64 and i386 tasks and never arm64
userspace. Signal delivery exposes the native x86 XSAVE layout for x87, SSE,
and AVX state and restores user edits through the matching ABI's signal-return
path. User RFLAGS follow Linux x86 for both ABIs: `execve()` starts a task with
0x202 (IF and bit 1), a signal return restores only `FIX_EFLAGS` (CF, PF, AF,
ZF, SF, TF, DF, OF, RF and AC), and a tracer may change those bits and NT.
IOPL, VM, VIF, VIP and ID stay the task's and IF stays set; the Darwin host
also sets IF and bit 1 on every entry to the task. RF, which IRET at CPL 3 and
a signal return may set, is gone when the next instruction starts, so a system
call that instruction makes, and its signal frame, never show it. A fault's
signal frame and a tracer's view at its stop show RF set, as the flags x86
saves for a fault do, and so does the frame of a signal that interrupts a
repeated string instruction between elements; a trap's show it clear.
`tests/integration/x86_64/run_guest_x86_64_rflags.py` checks this.

ICEBP delivers `SIGTRAP` with `TRAP_BRKPT` after itself. `#UD` is `SIGILL` with
`ILL_ILLOPN`. `#OF` from INT 4 or INTO, `#BR` from an i386 BOUND outside its
bounds and `#GP` reach the task as `SIGSEGV` with `SI_KERNEL` and no address,
`#OF` after the instruction and the two faults at it. A page fault's error code
carries the user bit. A protection fault's error code lacks the present bit.

An i386 tracer's register requests use the i386 layouts, as on Linux, with
`PTRACE_GETFPREGS` and `NT_PRFPREG` the i387 FSAVE image, and a tracer of
either ABI reaches the task's i386 TLS entries through the thread-area
requests. A tracer reads DR6 as x86 Linux shows it, 0xffff0ff0 with BS set
after a single step, and DR0 to DR3 and DR7 with x86's checks on the addresses
and lengths it writes. The slice has no hardware breakpoints, so a DR7 write
that enables one fails with `EINVAL`: gdb then reports "Couldn't write debug
register" for a hardware watchpoint or `hbreak`, while its software watchpoints
(`set can-use-hw-watchpoints 0`), breakpoints and single steps work. A tracer's
`orig_ax` (`orig_eax`) is the number of the system call the task is in and -1
at any other stop; writing it at a system call's entry stop runs that call
instead, and -1 skips the call and leaves AX as the tracer set it.
`tests/integration/x86_64/run_guest_x86_64_exceptions.py` checks these. Host
instruction execution is qualified against the pinned FEX handwritten x86-64
corpus; distribution and complete Linux syscall compatibility require separate
guest qualification. Both normal arm64 profiles accept `EM_AARCH64` only.
Android does not consume the x86_64 overlay.

The x86-family syscall dispatch is generated from the pinned Linux 6.18
`syscall_64.tbl` and `syscall_32.tbl` files. Both ABIs retain every table slot
through 469, including upstream `sys_ni_syscall` holes; generic compat handlers
and slice-owned adapters provide the i386 structure, argument-order, TLS, and
signal-frame ABIs. The UML entry path also provides syscall-user-dispatch so
Wine can interpose its NT syscall range before Linux syscall dispatch. Guest
qualification remains separate from structural table coverage. The slice
inherits the shared eBPF syscall, verifier, and cgroup BPF policy without a
product-specific configuration override.

Both use a 128 KiB virtually mapped task stack, a 128 TiB software-MMU task
range, a relocatable ET_DYN image, 100 Hz plus `NO_HZ_IDLE` with
high-resolution timers, built-in-only drivers, and the same host/kernel ABI. There is no platform-specific image or
address-space configuration axis.

The native mapping window contains guest RAM plus an auxiliary address-space
allowance equal to RAM, bounded from 1 GiB to 4 GiB. Vmapped task stacks and
other kernel virtual mappings use that allowance; their physical pages still
come from the guest's `mem=` allocation. The window additionally carries the
fixed vhost-user shared-memory reservation described below plus the stub pages,
added after that bound so the aperture never reduces the vmalloc allowance or
the configured guest RAM. The host emulator admits the same span
(`UML_NATIVE_VHOST_USER_SHMEM_RESERVATION` and `UML_NATIVE_STUB_PAGES` in the
top-level CMake layout); a host that reserves less faults on the kernel's own
stub write, so the two sizes move together.

The window lies inside every task's address range, and `mmap()` refuses any
user mapping that would enter it. A user TLB flush can still cover it: freeing
page tables widens the flush to each table's whole span, which starts inside
the window when a table also maps the first pages above it. Such a flush drops
and replays only the guest ranges beside the window, because the host would
take a range inside it for the kernel's own mappings.

Darwin UML negotiates the standardized vhost-user shared-memory-region
transport (`VHOST_USER_PROTOCOL_F_SHMEM_MAP`), obtains one region through
`VHOST_USER_GET_SHMEM_CONFIG`, and services acknowledged backend
`SHMEM_MAP`/`SHMEM_UNMAP` messages with exact descriptor, range, permission,
and owner validation. The kernel reserves a 1 GiB guarded guest-physical
aperture outside RAM, enforces 16 KiB mapping alignment under both guest page
profiles, and supports one mapping per 16 KiB aperture page through a
constant-time page-to-record index. Reset, disconnect, and release revoke every
mapping in bounded descriptor batches, and a request-stream lock serializes the
backend-request IRQ against the drain in every synchronous reply wait
([architecture](../../docs/architecture.md)) so two vCPUs cannot split one
framed request. The virtqueue and config interrupts either path records are
taken and cleared under the same lock before they are delivered, so a
recorded interrupt is never lost between two deliverers. Virtio-GPU
host-visible blobs use the same 16 KiB granularity without a private userspace
ioctl or a bridge ABI change.
The ACK line carries the same shared-memory transport, aperture geometry, and
mapping-capacity policy for its Venus Vulkan HAL. The two maintained kernel
lines adapt the topic to their own source histories while preserving the same
host-visible Virtio-GPU contract.

A Virtio-GPU file on a device with context initialization has no context until
it initializes one or its first transfer, submission, or resource creation
creates it. Every handle the file opened before then, typically a PRIME
import, is attached to the context when it is created, as a handle opened
afterwards is when it opens; closing one first drops it without a detach.
Upstream attaches only handles opened after the context exists, so the host
refused every transfer that named such a buffer. Android's gralloc mapper reads
an imported buffer exactly that way, which blanked every screenshot. The ACK
line carries the same change.

The Virtio-GPU primary plane accepts ARGB8888 as well as XRGB8888, so a GBM
client whose EGL config has alpha can set a mode. XRGB8888 stays the first
format, the one fbdev takes. The plane has no blend-mode property. The host
presents a scanout's colour channels and ignores its alpha byte, which is what
premultiplied alpha over the CRTC's black background shows. Only this line
carries the topic, because the ACK base already offers ARGB8888 and the other
32-bit RGB orders on the plane.

Both page profiles request the runtime's anonymous physical-memory token. The
kernel's linear physical window becomes the RAM root, so MMU and host-service
consumers do not retain a second full-span mapping. Guest RAM is committed on
demand: every chunk of the anonymous root starts released, `mem_init` commits
what memblock reserved, `arch_alloc_page()` commits a released chunk the first
time the allocator hands out a page of it, and the free-page reporting driver
releases each whole reported chunk through the bridge. Physical iOS wires only
committed chunks. `page_cache_trim` reclaims inactive page cache above a floor
(`page_cache_trim.floor_mb`, by default 1/32 of RAM, checked every
`page_cache_trim.interval_ms`) through memcg proactive reclaim, which leaves
anonymous memory alone. `CONFIG_VIRTIO_BALLOON` lets the host carve its GPU
memory out of guest RAM. UML removes virtio drivers from an exitcall that runs
after `device_shutdown()` has broken every virtqueue, so the balloon returns
its pages without waiting for a host answer when its queue is broken; otherwise
power-off with an inflated balloon never completes.

Every slice selects `HAVE_ALIGNED_STRUCT_PAGE` and `HAVE_CMPXCHG_DOUBLE`, as
native arm64 does; the x86-64 userspace slice keeps the arm64 kernel. SLUB
therefore updates a slab's freelist and counters with one CASP, which runs
directly on the host CPU, and `kmalloc_nolock()`, which BPF timers allocate
with, can use every cache. A build assertion checks that the FLATMEM memory
map's `SMP_CACHE_BYTES` allocation alignment covers the double-word alignment
this needs. The ACK line carries the same change.

Darwin's cooperative scheduler services timer deadlines and pending IPI vectors
at safe kernel spin, retry, TLB-walk, and `cond_resched()` boundaries, and in
`schedule()` when the caller stays runnable. The uaccess retry and TLB-walk
safe points poll through `cond_resched()`, which does so only without
`CONFIG_PREEMPTION`; both assert that at build time.
Every path that changes a CPU's
logical IRQ state outside `local_irq_*()`, including interrupt work run from an
idle wait, reports the change to lockdep as interrupt entry would; without
`CONFIG_TRACE_IRQFLAGS` the reports compile away. The IPI signal is only a
wake edge, so a task that yields in a retry loop would otherwise stop its CPU
whenever nothing else is runnable there: `tty_open()` retries that way while
the last
close of a terminal is in progress, and a shutdown that restarted a console
getty stopped for minutes, with `rcu_sched` stall reports, waiting for a timer
and a queued wakeup that the looping CPU never serviced. A pagefault-disabled
uaccess
never reports mmap-lock contention as a fault: `mmap_read_trylock()` refuses to
barge past a queued writer while the faulting retry of the same task still
steals the lock, so answering the try with `-EFAULT` made `futex_wait_setup()`
alternate a failing atomic read with a succeeding faulting one and never yield
the CPU that writer needs. The contended atomic walk runs under RCU instead,
which `MMU_GATHER_RCU_TABLE_FREE` keeps safe, and the page-table lock still
samples the entry.

An idle virtual CPU never blocks while one of its IPI vectors is pending. A
remote sender writes the idle wake pipe only when it takes the target's pending
mask from zero to non-zero and sends no signal to a target marked idle, so a
bit that is already set when the wait starts has no wake edge behind it. The
local irq_work vector sets its bit without a pipe edge and can be left set with
nothing queued, and a CPU that blocked on it would absorb every later remote
vector until an unrelated descriptor or timer woke it. The idle wait reads the
mask after publishing the idle state and polls instead of blocking.

Threads of one process replay their mappings to the host side by side; a user
`mm` has no replay lock, and the host orders its walkers instead. A batch
records the generation's invalidation epoch when it begins, Linux invalidates
the host range after it changes a PTE and before it frees the page, every
invalidation advances the epoch, and a batch publishes only while the epoch
still matches, so a walker that sampled a PTE before it changed cannot publish
it afterwards. Two walkers of one page can still publish out of order across a
change that needs no invalidation. Every such change makes the PTE more
permissive, so the stale batch leaves the page less accessible than Linux
allows and the next access replays it. A user `mm` queues exact page ranges,
while `init_mm`, which the host maps natively, still rounds to the 16 KiB host
page. A fault replays before Linux resolves it only when the PTE already grants
the access, and then brings its 16 KiB neighbours along; the replay after
resolution covers the faulting page and joins the pending snapshot under one
lock hold, so a sibling cannot take the range away and leave the task to return
to a page nobody has published. A user replay is published in batches of 64
pages which span the ranges of its snapshot, and only a rejected batch is walked
again, with a timer, IPI and scheduling checkpoint after every full batch and
every sixteenth rejection, so a whole-`mm` replay after a fork makes progress
while siblings keep invalidating. `init_mm` keeps its serialized walker.

`init_mm` has one synchronizing owner at a time and walks without a batch
budget. A synchronization its owner requests fails at once instead of
blocking, and the entry for callers that already hold an `mmap` lock accepts
only a user `mm`. Every synchronization takes and clears the pending ranges
under one lock hold, applies all of them, and requeues all of them when any
part fails, so no pending range is lost. Under 4 KiB pages one 16 KiB host
slot carries four `init_mm` PTEs: they are sampled under the PTE lock, the
whole host slot is dropped before the present quarters are mapped and the
absent ones unmapped, and the first failure stops the slot. The four samples
are not one atomic snapshot; a writer publishes its range after it changes a
PTE, so a later walk reapplies it. A kernel-mode fault publishes exactly its
Linux page, synchronizes `init_mm`, and resumes only when the host confirms
the access is backed; any other outcome panics instead of faulting again. On
both page profiles a nested mmu-gather flush keeps the range it collected
instead of becoming a whole-`mm` flush, because a Darwin range invalidation
already quiesces the generation's executors and advances its epoch.

Signal dispositions are process-wide, so the emulator's device and renderer
threads share UML's `SIGSEGV` and `SIGBUS` handlers even though they own no
Linux task. A synchronous fault enters the guest path only from a virtual CPU
carrier, or from the boot thread while it still owns CPU0. Every other fault is
reported with its real host thread and literal addresses before the default
host disposition terminates the faulting instruction.

A public stop reaches every carrier: one leaving translated guest code honours
it before its task continues, and an idle carrier's wait includes the stop
descriptor. The last-ditch handler for a fatal host signal exits at once
without Linux exitcalls, because the carrier that receives a process-directed
signal may be running its vCPU's idle task.

The Darwin network receive path uses NAPI, and the display-mapped absolute
pointer is a direct touchscreen.
Direct UBD images advertise discard ranges up to 128 MiB and service each range
with one host hole punch. The project adds no behavior to upstream UML's COW
implementation, and Apple launchers never construct a COW image pair.

Lifecycle quiesce uses full Linux system suspend. The management console
acknowledges only after the suspend entry boundary and remains the explicit
wake source, so monotonic guest uptime excludes time while an Apple host has
frozen the application. Multi-vCPU suspend parks secondary carriers through CPU
hotplug and restores them before guest tasks resume. The console socket is
`/tmp/uml-<umid>-mconsole`, or `<dir>/mconsole` when the host passes
`uml_dir=<dir>`, a directory owned by that machine alone; a path that does not
fit Darwin's 104-byte `sun_path` is refused, never truncated.

Loadable modules remain disabled. The required guest filesystems, networking,
Virtio devices, cgroups, BPF interpreter, zram, zswap/zstd, and supported LSM
policy are built in. Hostfs is disabled. Deliberately unsupported kernel
features are reflected in the LTP disabled manifest rather than enabled solely
for test count.

The kernel exposes its BTF at `/sys/kernel/btf/vmlinux` for CO-RE programs.
BPF runs on the interpreter; no BPF code is generated at run time. Helpers
that take a callback, such as `bpf_loop`, `bpf_for_each_map_elem`, and
`bpf_timer_set_callback`, reach an interpreted callback through a fixed pool of
1024 built-in entry points. Each callback subprogram of a loaded program holds
one until the program is freed, and a load that finds none free fails with
`ENOSPC`. The interpreter still rejects kfunc calls, and tail calls in a
program that has callbacks or other subprograms; `bpf_wq`, which only kfuncs
reach, is therefore unavailable. Tracing program types (kprobe, uprobe,
tracepoint, raw tracepoint, iterator) need `CONFIG_BPF_EVENTS`, which UML does
not provide.

Kernel IP autoconfiguration is disabled. Writable guest images start their own
DHCP client and DNS resolver after init begins; launchers do not need kernel
`ip=` configuration for those images.

The framebuffer console uses standard VT/fbcon on Virtio-GPU. Host logs use
`ttyS0`; four serial lines and the standard Virtio-console driver are built in.
The legacy UML stdio console, DRM log client, legacy BSD PTYs, and loadable
module path remain disabled.

Zswap is built in and enabled with zstd but allocates no pool until the guest
activates backing swap. Normal desktop launchers do not create backing swap and
must not count zswap as guest memory.

## Standalone build and publication

Build each profile outside the source tree:

```sh
kernel/mainline-6.18/build/build-kernel.sh \
  --slice arm64 --build /case-sensitive/build-arm64-16k --page-size 16k
kernel/mainline-6.18/build/build-kernel.sh \
  --slice arm64 --build /case-sensitive/build-arm64-4k --page-size 4k
kernel/mainline-6.18/scripts/prepare-source.sh --slice x86_64
kernel/mainline-6.18/build/build-kernel.sh \
  --slice x86_64 --build /case-sensitive/build-x86_64-4k --page-size 4k
```

Publish each completed build with
`build/publish-artifact.py`. The publisher requires a clean replay at the
tracked final tree, validates resolved policy and ELF/ABI geometry, and copies
only the compact runtime/support bundle, with the kernel image's DWARF
stripped (see [Toolchain](#toolchain)). It never builds, fetches, or changes a
source checkout. Use the script's `--help` for output and release options.

`artifacts/accepted-16k.env` and `accepted-4k.env` select reviewed arm64 local
publications below `.build/kernel/artifacts`.
`slices/x86_64/artifacts/accepted-4k.env` independently selects the x86_64
userspace publication. Artifact identity includes the slice, so an arm64 4 KiB
kernel cannot satisfy an x86_64 selection. Apple products validate the whole
selected bundle and derive paths from its manifest; they do not inspect source
or Kbuild state.

## Toolchain

`build/toolchain/darwin.env` owns portable compiler/linker defaults and the
project compatibility headers used by Darwin host tools. Linux 6.18 requires a
compiler with `__counted_by` type-expression support; the preflight checks this
before Kbuild. Select a compatible upstream LLVM toolchain explicitly when the
default Apple compiler lacks the feature.

The documented `UML_KERNEL_*` variables may override compiler, host compiler, linker, binutils, make, cross prefix, and job
count. Companion LLVM tools must match the selected compiler family.

Every kernel generates BTF, so the build also needs pahole and a static
libelf. Both come from the `kernel-host-tools` dependency product, built from
pinned elfutils, dwarves, and libbpf sources:

```sh
dependencies/prepare.sh --product kernel-host-tools
dependencies/prepare.sh --archive-manifest dependencies/kernel-host-tools/archives.tsv
dependencies/build-kernel-host-tools.sh
```

`UML_KERNEL_HOST_TOOLS_PREFIX` selects the prefix (default
`.build/dependencies/kernel-host-tools`) and `UML_KERNEL_PAHOLE` may select a
different pahole. The build never searches `PATH` for either: the preflight
fails before Kbuild when pahole is missing or older than v1.29, the first
release whose parallel encoding is always ordered, or when the prefix lacks
libelf. Kbuild's pkg-config lookups see only the prefix, whose real `elf.h`,
`libelf.h`, and `libelf.a` serve every host tool, including `resolve_btfids`.
`build/toolchain/darwin-host` supplies only the Linux host APIs Darwin lacks;
the Linux system calls that libbpf reaches there fail with `ENOSYS`, because a
host tool never drives a running Linux kernel.

Host objects are compiled without debug information whenever BTF is enabled.
They describe host C library types under the kernel's type names, and pahole
would otherwise encode those definitions into vmlinux BTF.

The kernel links with full DWARF 5, which is only pahole's input. Frame
pointers are on for the stack walker, as the
[common README](../common/README.md) describes. The publisher's `--objcopy`,
the build's own `llvm-objcopy`, strips every `.debug_*` section from the
published `vmlinux`; the artifact verifier rejects DWARF and requires an
allocated `.BTF` section. Stripping drops only the
`STT_FILE` symbols and the locals that describe debug sections. Every function
and data symbol, `.dynsym`, and `System.map` stay, so crash symbolization is
unchanged.

The canonical bridge lives under [`../common/abi`](../common/abi/). Ordinary
build and replay verification use `kernel/common/abi/sync.sh --verify`; only an
intentional ABI change regenerates copies and the affected kernel topic.
