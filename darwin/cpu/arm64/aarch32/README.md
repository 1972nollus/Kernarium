# AArch32 decoder

`uml_arm64_aarch32_decoder` is the one decoder for the 32-bit Arm line. Both
arm64 engines and the AArch32 semantic library share it. It decodes A32,
T16 and T32 words, in the IT state the caller holds, and answers with the
instruction's form, condition, length, operands and IT effect. It includes no
engine, holds no state, and is a CPU-layer `shared` target.

## Contract

`decode.hpp` is the interface:

- `decode_a32(word, profile)` and `decode_thumb(hw1 << 16 | hw2, it, profile)`
  return an `Instruction`. `thumb_length(hw1)` says how many bytes a Thumb
  instruction occupies before the second halfword is read.
- `Status` is `ok`, `nop` or `undefined`. An `undefined` instruction carries a
  `Reason`: `unallocated`, `unpredictable`, `profile` or `feature`. Anything
  the profile does not implement, and every UNPREDICTABLE encoding, is
  undefined; the decoder never guesses. The engine raises the
  illegal-instruction exit for it.
- `Profile` is a `Level` (`none`, `base`, `simd`, `complete`, as
  `A32Support`) and a `FeatureSet` for the optional extensions the host has.
  An instruction above the level is undefined with reason `profile`; one of a
  feature the profile lacks is undefined with reason `feature`.
- `Instruction::cond` is the condition the instruction executes under: its own
  field, the IT block's condition, or 14. `in_it` and `last_in_it` describe a
  Thumb instruction's place in a block, `next_it` is the IT state after it,
  and an IT instruction reports `it_length`, the instructions its block holds.
  The caller advances its IT state with `next_it` and treats a block as
  running until `next_it` is zero.
- `Instruction::operands` holds what the XML's Decode pseudocode computes for
  the form, named for its variables (`d`, `n`, `m`, `t`, `imm32`, `setflags`,
  `shift_t`, `registers`, `esize`, ...). A member the form's pseudocode does not
  set is zero. A `bits(N)` value is its bit pattern; `imm32` is the 32-bit
  pattern, and an integer is its value. `carry_flags` means the carry-out of
  an expanded immediate is the carry flag; `carry` holds it otherwise.
- `Instruction::sysreg` names the register of a permitted MCR, MRC or MRRC:
  TPIDRURO and TPIDRURW, the generic timer's CNTFRQ and CNTVCT, and the CP15
  barriers. The barriers run only when the guest's CP15BEN is set, which the
  engine tests; every other coprocessor access is undefined.
- `Instruction::info()` returns the form's table entry: the XML encoding name,
  its mnemonic, the level and feature it needs, whether it is conditional, and
  static traits (loads, stores, exclusives, the kinds of PC write, barriers,
  hints, exceptions) scanned from the XML's Execute pseudocode.

The profile is Armv8-A AArch32 at EL0 (see
[`../../../../docs/architecture.md`](../../../../docs/architecture.md) and
[`../../../../docs/a32-instruction-coverage.md`](../../../../docs/a32-instruction-coverage.md)).
The decoder implements these choices on top of the XML:

- SWP and SWPB, which Armv8 AArch32 does not have, decode as unallocated;
  SETEND, SETPAN, SRS, RFE, ERET, HVC, SMC, HLT, DCPS, the banked-register and
  user-register forms of MRS, MSR, LDM and STM, and LDC and STC are undefined
  at EL0;
- MRS and MSR reach the APSR only, and VMRS and VMSR reach FPSCR only
  (including `VMRS APSR_nzcv, FPSCR`); an MSR whose x field (mask bit 1) is
  set would write PSTATE.E, which the profile does not implement (SETEND is
  undefined), so it is undefined, and its c field is ignored at EL0;
- CPS is a NOP at EL0 and BXJ behaves as BX;
- an A32 data-processing instruction with S set and Rd 15 (an exception
  return) is UNPREDICTABLE at EL0, hence undefined;
- an encoding the XML marks should-be-zero or should-be-one that differs is
  UNPREDICTABLE, hence undefined;
- the hint encodings of features the profile lacks (ESB, TSB, CLRBHB) are
  NOPs, as are the reserved hint encodings whose should-be bits (SBO in an A32
  hint's bits 15:12; in a T32 hint, SBO in the first halfword's low nibble
  and SBZ in bit 13 and bits 11:8 of the second) hold; one that differs is
  UNPREDICTABLE, hence undefined.

## The table

`a32_encodings.hpp`, `a32_encodings.cpp` and `a32_operand_decode.cpp` are
generated by `tests/tooling/arm64/generate_a32_encoding_table.py` from the
pinned Arm AArch32 XML release, the profile's choices
(`tests/tooling/arm64/a32_profile_policy.py`) and LLVM MC 22.1.8, a
tooling-time oracle that no build uses. Never edit them.

- A `Form` is one XML encoding. A `Row` is one partition of the A32 or T32
  encoding space that the XML's encoding index allocates to a form; the index
  partitions the space exactly, so the rows that remain after the unallocated
  ones are dropped decide every word. A decision tree per instruction set
  selects the candidate rows, which the row's mask, value and constraints then
  confirm.
- An operand program is a form's Decode pseudocode translated to C++ by
  `a32_operand_codegen.py`. The helpers it calls are Arm's shared
  pseudocode functions in `decode_support.hpp`. A construct the translator
  does not know fails the generation.
- The unit test `arm64-aarch32-decoder` decodes the stored sample words of
  every row and the whole 16-bit Thumb space and compares the answers
  against `a32_expected.py`, an independent evaluation of the same pseudocode
  and rules, and against what LLVM MC decodes
  (`tests/unit/arm64/aarch32_decoder/`). `docs/testing.md` has the commands.

## The semantic library

`uml_arm64_aarch32_semantics` is the one C++ implementation of what the
decoder accepts, for the engines' slow paths and long tails and for the
corpus's model lane (`semantics.hpp`). It follows the SVE library: a
CPU-layer `shared` target that includes no engine, works on `CpuState` alone
and reaches guest memory only through the caller's `A32Memory`.

- `execute_a32(cpu, instruction, memory)` runs one decoded instruction;
  `step_a32(cpu, memory, profile)` fetches, decodes in `cpu.a32_itstate`
  and executes one, which is the single-instruction entry for what an engine
  cannot translate as a block. Calling it until ITSTATE is zero leaves an IT
  block as the architecture does.
- `A32Memory::translate()` returns the host address of a guest byte, valid to
  the end of its guest page, or nothing. The library splits every access at
  a page and reports the address and the access of a fault itself, so an
  engine records it where its own exit convention wants it. `stored()` reports
  each host range a store wrote, for the engine's reservation and code
  invalidation.
- The result is a `StepEvent`: `retired`, `supervisor_call` (PC and ITSTATE
  advanced), `breakpoint` (PC and ITSTATE unchanged), `undefined`,
  `memory_fault` (the 32-bit architectural address, translation or
  alignment), `pc_alignment` and `fatal`. A fault leaves the registers, PC and
  ITSTATE as the instruction found them, except that STM and PUSH store the
  words ahead of the faulting one and leave the base register unchanged.
- The exclusives use `CpuState`'s record (`exclusive_address`,
  `exclusive_key`, `exclusive_value`, `exclusive_value2`, `exclusive_size`):
  a load-exclusive records the host address and the value, and a
  store-exclusive is a host compare-and-swap against it. Ordinary stores leave
  the monitor to the engine.
- `a32_semantics_covers(form)` holds for every form up to
  `a32_semantics_level()`; any other word reaching `execute_a32()` is `fatal`,
  an internal error. The library-exit counters count each call by form.

The library covers `base`, A32 and T32: integer, memory (single, multiple,
exclusive, acquire/release), branch, IT and system forms. Above it, it covers
the VFP and Advanced SIMD memory forms (VLDR, VSTR, VLDM, VSTM, FLDMX, FSTMX,
VLDn and VSTn), whose structure loads and stores read all their memory before
they change a register and gather it all before they store, and whose VSTM and
FSTMX store the words ahead of a fault like STM. The VFP and NEON arithmetic
and the Armv8 extension levels follow.
